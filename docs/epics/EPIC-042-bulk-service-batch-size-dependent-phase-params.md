# EPIC-042: Bulk-service с batch-size-зависимыми параметрами Erlang/H2

- **Статус:** done
- **Создан:** 2026-09-30

## Цель

`BulkServiceErlangCalc`/`BulkServiceH2Calc` (EPIC-035/036) сейчас используют ОДИН набор
параметров фазового распределения независимо от размера батча. `BulkServiceMM1Calc` (EPIC-012)
уже поддерживает callable-ставку, зависящую от размера батча (LLM/GPU-мотивация: большие батчи
обрабатываются с другой эффективностью) — перенести эту гибкость на фазовый (Erlang/H2) случай.

## Контекст

Обзор: [../research/bulk-service-batch-size-dependent-phase-params-2026.md](../research/bulk-service-batch-size-dependent-phase-params-2026.md).
Кандидат №3 из очереди 2026-09-30. Механическое расширение — параметризовать переходы по
текущему размеру батча `i`, а не константой; число фаз (`k` у Erlang, структура H2) остаётся
фиксированным — меняются только ставки/вероятности. Найдена и исправлена тонкость у H2: при
завершении батча сплит на ветви НОВОГО батча должен использовать `p1(take)` (размер нового
батча), а не `p1(i)` (размер завершившегося) — легко перепутать местами.

## Задачи

- [x] Callable `rate(i)` для `BulkServiceErlangCalc`; callable `p1(i)/mu1(i)/mu2(i)` для
      `BulkServiceH2Calc`, с осторожностью про «чей размер батча» на каждом переходе.
- [x] Реализация для обоих калькуляторов + тесты (регрессия к константным параметрам, DES
      cross-validation с реально разными по размеру батча параметрами).
- [x] Документация, память.

## Результаты

Оба калькулятора (`most_queue/theory/batch/bulk_service_erlang.py`,
`most_queue/theory/batch/bulk_service_h2.py`) теперь принимают в `set_servers()` либо скаляр
(обратная совместимость, поведение не изменилось), либо callable `f(batch_size) -> value` для
каждого параметра — по аналогии с уже существующим `BulkServiceMM1Calc.set_servers(mu)`.

**Тонкость у H2, учтённая при реализации:** при переходе «батч завершается → батч размера `take`
стартует» ставка исходящего перехода берётся у ЗАВЕРШИВШЕГОСЯ батча (`mu_фаза(i)`), но вес сплита
по ветвям НОВОГО батча должен использовать `p1(take)`, а не `p1(i)` — эти два размера батча могут
отличаться. Erlang этой проблемы не имеет (продвижение фазы всегда для ТЕКУЩЕГО батча).

`mean_batch_service` (используется в `get_w() = E[V] - mean_batch_service`) обобщён с константы
на взвешенное по занятому времени среднее по фактическому распределению размеров батча из решённого
стационарного распределения — тот же уровень приближения «только среднее», что и раньше.

**Валидация:** оба калькулятора сверены с независимой DES при ДЕЙСТВИТЕЛЬНО зависящих от размера
батча параметрах (не только на вырожденном константном случае); регрессия к константному случаю
проверена явно (лямбда-обёртка `lambda _i: const` должна давать тот же результат, что и прямой
скаляр). Существующие 7+6=13 тестов EPIC-035/036 остались зелёными без изменений (только два
прямых обращения к переименованным атрибутам `.rate`→`.rate_fn`, `.p1/.mu1/.mu2`→`.p1_fn/.mu1_fn/
.mu2_fn` в тестах обновлены).

**Тесты:** 4 новых теста (2 в `test_bulk_service_erlang.py`, 2 в `test_bulk_service_h2.py`) —
DES cross-validation с батч-size-зависимыми параметрами + регрессия к скалярному случаю. Полный
набор тестов (вместе с EPIC-040/041/043): 769 passed, 0 failed (410s, `pytest tests/ -n auto`).

**Резерв:** batch-size-зависимое число фаз (заметно сложнее — тот же класс, что и EPIC-041);
точные моменты (остаются только средние, как и раньше).
