# EPIC-099: измерения serving, калибровка и совместный SLO

- **Статус:** done (измерительный инструментарий и диагностический пилот)
- **Дата:** 2026-11-14
- **План:** [LLM/GPU](../roadmaps/llm_gpu_growth_roadmap.md), шаги 2–3.

## Зафиксировано до подгонки

Импортировать подробные результаты vLLM bench serve по контракту исходника
`v0.33.0rc3`, commit `4ba787ec9959e566d3b587a796dff07673324da5`.
Клиентские `queue_times` не являются серверным ожиданием. Не восстанавливать
совместный TTFT/TPOT SLO по агрегированным процентилям.

Реальные открытые данные: `MarcoPizeta/flash-next-rtxpro6000-bench`, commit
`fcdded55d1415d2a9b9256e58666d7c993cb5c2a`, текущий каталог `results/`,
vLLM MTP off, входы 1024/8192/32768, concurrency=1, прогоны r1/r2 для
обучения, r3 для проверки. Клиент этого набора — SGLang; отдельный адаптер
сохраняет различие между временем последнего потокового события и полным
временем HTTP-запроса. Версии и ограничения приводятся в манифесте.
Исторический `results-v1-seed42/` с повторным использованием seed исключён
по описанному авторами исправлению протокола, до подгонки результатов.

Уточнение после чтения ограничений pinned README, **до первой подгонки**:
даже в текущем наборе первый запрос каждого прогона использован для warmup
и имеет заниженный TTFT. Исключить index0 из калибровки и её проверки во всех
девяти файлах одинаково: train30, heldout15. В расчёте SLO сохранить все
измеренные запросы, с явным указанием состава выборки. Дополнительных исключений
по величине задержки не делать.

Для изолированной заявки длины n/m рассматривается простой эффективный закон:

- TTFT = delta + 2 alpha + beta (n+1) + gamma (2n+1).
- TPOT = alpha + beta + gamma (n+(m+2)/2), m>1.

alpha/beta/gamma соответствуют принятому двухстадийному суррогату;
delta — дополнительная постоянная задержка клиентского наблюдения. Физически
разложить её на сеть, frontend и другие компоненты по этим данным нельзя.
Параметры неотрицательны; NNLS с масштабированием столбцов, проверкой ранга,
равным весом двух метрик после деления на их обучающие средние. Порог
диагностической пригодности: медиана абсолютной относительной ошибки каждой
метрики на r3 ≤ 15%. Порог и split не меняются после просмотра результата.
Непрохождение порога является результатом; не подменять его подбором split.

SLO примера: TTFT ≤ 0,5 с и TPOT ≤ 0,02 с одновременно. Это иллюстративные
пороги, не требования автора измерений. Ошибки/отмены входят в знаменатель,
незавершённые дают явный интервал неопределённости. Для ответа из одного токена
TPOT не определён; отсутствие последующих токенов считается выполнением этого
условия, как в goodput vLLM, и отдельно отражается в счётчиках.

Времена ожидания сервера в выбранных открытых данных отсутствуют. Калибровка
очереди и проверка под нагрузкой требуют дополнительных измерений; даже хороший
результат на одиночных запросах не закрывает этот пункт.

## Результаты

Реализованы подробные адаптеры vLLM и SGLang, единое представление исходов
запросов, совместный TTFT/TPOT SLO, границы для незавершённых запросов и
адаптер токенового DES с цензурированием на заданном горизонте. Пример включает
12 отдельно инициализированных синтетических прогонов и интервалы по их
итоговым показателям. Исходные открытые измерения сохранены с MIT-лицензией,
описанием оборудования, версиями и SHA256.

Изолированный пилот завершён с отрицательным результатом по принятому критерию:
медианная абсолютная относительная ошибка TTFT — 63,40%, TPOT — 9,18%.
Параметры и разбиение после проверки не менялись. Этот закон не принимается
как проверенный прогноз TTFT для указанного стека. Отсутствие серверных времён
ожидания не позволяет оценить качество расчёта очереди.

Калибровка очереди и проверка под нагрузкой явно перенесены в оставшуюся часть
шага 2 [плана LLM/GPU](../roadmaps/llm_gpu_growth_roadmap.md): требуются новые
серверные измерения, профили итераций и зафиксированная политика кэша/warmup.
Завершение этого эпика означает готовность измерительного инструментария и
воспроизводимого диагностического пилота, а не выполнение цели по точности.

Проверки реализации: 49 тестов, включая восстановление заранее заданных
параметров по отдельному токеновому DES, ручные примеры совместных исходов,
цензурирование и валидацию импортируемых массивов. Итоги общего тестирования
и упаковки приведены в [отчёте выпуска](../releases/2.11-validation.md).
