## Цель и происхождение

Единственный пункт roadmap, где пробел признавал наш собственный код:
`MG1PSCalc` писал в docstring «Only mean sojourn/waiting values are produced:
higher PS sojourn moments require the Yashkov/Ott transform machinery and are
left for a follow-up», и `MGnPSCalc` это повторял. Закрыть свой же
зафиксированный долг логичнее, чем начинать новое.

Содержательно это не косметика. Среднее условное время пребывания
`E[V(x)] = x/(1−ρ)` **нечувствительно** — оно не зависит от формы распределения
времени обслуживания вообще. Ничто выше среднего этим свойством не обладает.
Значит по одному среднему нельзя сказать ничего о риске: две нагрузки с
одинаковым средним временем обслуживания дают одинаковое `E[V]`, одинаковое
число заявок в системе — и разную дисперсию. Для прикладной стороны (разделение
GPU между одновременными запросами) вопрос «уложится ли запрос в дедлайн» без
второго момента не ставится.

## Конструкция

Величина, **обратная** преобразованию условного времени пребывания,
раскладывается в аккуратный степенной ряд (теорема 3.1):

```
1/v(r,u) = sum_n (r^n/n!) xi_n(u),
xi_n(u)  = n/(1-rho)^n * int_0^u (u-y)^(n-1) W^((n-1)*)(y) dy        (3.2)
```

где `W` — обычное распределение времени ожидания в M/G/1 с дисциплиной FCFS
(Поллачек–Хинчин), `W^(m*)` — его m-кратная свёртка. Сопоставление этого ряда с
рядом для самого преобразования даёт рекурсию (теорема 3.2):

```
v_n(u) = sum_{i=1..n} C(n,i) v_{n-i}(u) xi_i(u) (-1)^(i+1)           (3.7)
```

Рекурсия выведена заново из тождества `v · (1/v) = 1`, а не взята на веру;
совпала с напечатанной.

### Разрешение неоднозначности в (3.2)

В формуле (3.2) знак `*` назван «свёрткой Стилтьеса», но при буквальном
прочтении `int_0^u (u-y)^(n-1) dW^((n-1)*)(y)` получается `xi_1 = 1/(1−ρ)`,
тогда как по (3.9) должно быть `xi_1 = u/(1−ρ)`. Верное прочтение — обычная
свёртка функции `u^(n-1)` с функцией `W^((n-1)*)`, то есть
`int_0^u (u-y)^(n-1) W^((n-1)*)(y) dy`. Проверено дважды: при `n = 1` даёт
`u/(1−ρ)` (3.9), при `n = 2` — ровно формулу дисперсии (3.10). Эквивалентная
запись, использованная в коде:

```
xi_n(u) = (1-rho)^-n * E[(u - S_{n-1})^n ; S_{n-1} <= u]
```

где `S_m` — сумма `m` независимых копий времени ожидания FCFS. Это и делает
возможным фазовое вычисление.

### Как снята «практическая невычислимость»

Сам Яшков в заключении пишет, что точные выражения «содержат интегральный член,
что затрудняет точное вычисление с практической точки зрения», и литература
ответила границами (Cheung, van den Berg, Boucherie, Queueing Systems 53:7–18,
2006) и приближениями. Это свойство постановки для произвольного `B`, а не
результата: при фазовом времени обслуживания фазовыми остаются все объекты
цепочки.

- равновесное (остаточное) распределение `PH(tau, T)` — это `PH(pi, T)` с тем же
  генератором и `pi = tau(-T)^-1/mean`;
- время ожидания M/G/1 — геометрическая сумма таких, то есть атом массы `1−ρ` в
  нуле плюс дефектное `PH(rho*pi, T + rho*t*pi)` (выведено и проверено через
  тождество Шермана–Моррисона);
- m-кратная свёртка — обычное блочно-двухдиагональное фазовое распределение;
- `int_0^u (u-y)^k e^{Ay} dy` — один блок одной матричной экспоненты (тождество
  Ван Лоана), без обращения матриц.

Поэтому для фазового обслуживания — а именно так библиотека представляет
обслуживание общего вида, подогнанное по моментам, — моменты получаются точно,
из нескольких матричных экспонент малого размера, вообще без квадратур.

### Постоянные заявки: из теоремы 3.3 извлечено больше, чем в ней сформулировано

Теорема 3.3 даёт две формулы — для среднего и дисперсии при `K` постоянных
заявках бесконечного размера. Но лежащее в её основе тождество
`v_K(r,u) = v(r,u)^(K+1)` говорит сильнее: время пребывания при `K` постоянных
заявках распределено **точно как сумма `K+1` независимых копий** времени
пребывания без них. В коде это реализовано возведением ряда `1/v` в степень
`K+1` перед применением той же рекурсии, что даёт **все** моменты, а не только
первые два.

Побочно это дало бесплатную проверку третьего момента, которую не покрывает ни
одна опубликованная формула: для суммы двух независимых копий
`E[(X+Y)^3] = 2E[X^3] + 6E[X^2]E[X]` — выполняется до `1e-9`.

## Проверки

Пять эталонов, ни под один из которых реализацию нельзя подогнать:

| эталон | результат |
|---|---|
| Нечувствительность `E[V(x)] = x/(1−ρ)` при 3 формах обслуживания × 3 нагрузках | до `1e-11` |
| Дисперсия M/M/1-PS против замкнутой формы, выведенной из (3.10) | `1e-13`…`1e-16` |
| Асимптотика Яшкова `Var ~ u²ρ/(1−ρ)²` при `u → 0` | отношение `0.99999` при `u = 1e-4`, одинаково для всех трёх форм |
| Уравнение (3.10) независимой квадратурой от `W(x)` | `1e-6` (уровень квадратуры) |
| Среднее времени ожидания фазового `W` против Поллачека–Хинчина | до `1e-12` |

**Первая строка — самая сильная проверка из возможных.** Реализация нигде не
использует нечувствительность: первый момент считается тем же трудным путём,
что и остальные, — через `xi_1`, равновесное распределение и фазовое время
ожидания, — и обязан попасть ровно в значение, которого ей не сообщали.

Дисперсия упорядочена по изменчивости обслуживания, как и должна быть
(при `ρ = 0.6`, заявка размера 2, во всех случаях `E[V] = 5`):

| обслуживание (среднее 1) | `Var[V(2)]` | `CV[V(2)]` |
|---|---|---|
| Erlang(3), cv = 0.58 | 10.84 | 0.659 |
| экспоненциальное, cv = 1 | 11.69 | 0.684 |
| H2, cv = 2 | 12.38 | 0.704 |

## Урок: способ сравнения оказался важнее самого сравнения

Первая версия сверки разбивала заявки по размеру на интервалы и сравнивала с
`v_n` в середине интервала. Результат — до **7.6σ**, причём расхождения меняли
знак между наборами. Разбор занял минуты, потому что первый момент точен:
отклонение по нему означало, что сравнивается не то. Так и есть —
`E[размер | размер в интервале] ≠ середина интервала`, и знак смещения всюду
совпадал со знаком наклона плотности распределения размеров на интервале.

Замена — **парное сравнение**: каждая смоделированная заявка сопоставляется с
теорией, вычисленной в её **собственном** размере, и сравниваются выборочные
средние `V^n` и `v_n(size_j)` по одним и тем же заявкам. Ошибка выборки по
размерам сокращается, и остаётся проверка `v_n(·)` поточечно по всему диапазону
размеров. Отклонения сразу упали до долей сигмы.

Приём общий: **если теория даёт величину, условную по непрерывному параметру, не
разбивай на интервалы — сопоставляй поточечно.** Это третий инструмент в том же
ряду, что парная разность из EPIC-075 и контрольный опыт на вырожденных
параметрах из EPIC-076.

Отдельно стоит записать, что при `ρ = 0.64` первая сверка дала −2.3σ по всем
трём моментам, и это снова оказался бюджет имитации, а не теория: на 1.2 млн
заявок × 8 прогонов отклонение стало +0.63σ / +0.31σ / −0.51σ. Первый момент
здесь работает как встроенный контроль — он точен, поэтому его отклонение
калибрует смещение имитации, и отдельный контрольный опыт (как в EPIC-076) не
понадобился.

## Границы применимости, названные прямо

- **Дисперсия зависит от формы распределения обслуживания.** Если передать
  только моменты и позволить `set_servers_from_moments` подобрать форму, ответ
  точен для **подобранного** закона, а не для любого закона с теми же моментами.
  Среднего и числа заявок это не касается — они нечувствительны. Оговорено в
  docstring метода и в документации.
- **Многоканальный случай `n > 1` закрыть не удалось, и не из-за нехватки
  усилий.** Рекурсия Яшкова построена на распределении времени ожидания в M/G/1
  с FCFS и относится именно к одноканальному случаю. Нечувствительность, из-за
  которой число заявок в `MGnPSCalc` совпадает с M/M/n, на условное время
  пребывания не распространяется, поэтому результат для `n = 1` нельзя просто
  пересчитать. Формулировка в docstring `MGnPSCalc` исправлена: раньше там
  стояло «отложено до следующего раза», что вводило в заблуждение.
- **Одна численная операция осталась** — внешнее интегрирование по
  распределению времени обслуживания в `get_v`/`get_v_moments`. Её точность
  проверяет себя сама: первый момент обязан вернуться равным `b1/(1−ρ)`
  (на практике `~2e-7`).

## Результаты

Закрыт пункт Р3 roadmap и собственный зафиксированный долг библиотеки.
`MG1PSCalc` перестал быть «только средние»: доступны точные начальные моменты и
дисперсия условного времени пребывания, безусловные моменты и случай `K`
постоянных заявок. Моменты подаются в [слой SLA](../models/sla.md) и дают
вероятность нарушения дедлайна для разделяемого ресурса — величину, которую по
одному нечувствительному среднему получить нельзя в принципе.

Следующий пункт roadmap — Р4 (Bhat 1966, GI/M/2 с интенсивностью, зависящей от
числа занятых приборов).
