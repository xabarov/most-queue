# EPIC-070: Нетерпеливые заявки в многоканальном bulk-service (EPIC-068 × EPIC-069)

- **Статус:** done
- **Создан:** 2026-10-06
- **Завершён:** 2026-10-07
- **Roadmap:** резерв EPIC-069 («Что НЕ сделано»: «Нет конструкции, одновременно дающей нетерпение и несколько каналов»)

## Цель

Добавить марковское нетерпение (ставка `gamma`, конвенция `MM1Impatience`) к
`BulkServiceMultiserverCalc` (`c`/`n` идентичных каналов, общая очередь, EPIC-069) —
первая из трёх комбинаций расширений, отмеченных как резерв в «Ограничениях» статьи
batch-service-sla после EPIC-068/069.

## Почему это низкий риск (проверено до старта реализации)

В отличие от двух других резервных комбинаций (H2+нетерпение, несколько каналов +
фазовое/batch-size-зависимое обслуживание — обе требуют НОВОЙ конструкции состояния),
эта комбинация **переиспользует уже провалидированные кусочки EPIC-068/069
практически без изменений**:

1. **`_solve_pi()`**: тот же паттерн, что в `BulkServiceMM1Calc`/`BulkServiceErlangCalc`
   (EPIC-068) — добавить `if j>=1 and gamma>0: add(s, ..., j*gamma)` к существующему
   построению генератора `BulkServiceMultiserverCalc`.
2. **Конструкция ожидания помеченной заявки**: EPIC-069 уже показал, что при
   батч-размер-независимом `mu` агрегированная ставка освобождения любого из `n`
   каналов равна ровно `n*mu` независимо от состава занятости, и поэтому переиспользует
   `abandonment_chain` с `rate_first=rate_ahead=n*mu` при `gamma=0` (без нетерпения).
   Эта же конструкция, с РЕАЛЬНЫМ `gamma>0` (не зафиксированным в 0), даёт конструкцию
   и для нетерпения — ставка `n*mu` сама по себе не зависит от того, конкурирует ли
   она с нетерпением помеченной заявки или нет.
3. **Формула момента**: уже выведена и один раз исправлена в EPIC-068 (`n+1`, а не `n`
   применений `(-T)^{-1}` для вектора награды `serve_rate`) — переиспользуется как есть.

**Эмпирическая проверка (до начала реализации, не входит в сам код библиотеки):**
независимый DES (`a=2,b=4,n=3,lam=1,mu=0.5,gamma=0.3`) против ручной сборки тех же
трёх кусочков дал `P(уход)=0,13385` (DES: `0,13369`) и `E[W|обслужена]=0,39650`
(DES: `0,39646`) — совпадение в пределах шума выборки. По пути в собственном
черновом скрипте (не в библиотеке) была переоткрыта та же ошибка формулы момента,
что и в EPIC-068 (не хватало одного применения `(-A)^{-1}`), что лишний раз
подтверждает: единственная содержательная находка здесь уже сделана ранее, остаётся
аккуратная сборка.

## Задачи

- [x] `BulkServiceMultiserverCalc.__init__`: параметр `gamma: float = 0.0` с валидацией
      (`>= 0`), по конвенции `BulkServiceMM1Calc`/`BulkServiceErlangCalc`.
- [x] `_solve_pi()`: добавлен `j*gamma` отток (busy и idle состояния).
- [x] `get_abandonment_prob()`: реализован через `_abandon_chain_for_state()`,
      переиспользующий `abandonment_chain(n*mu, 1, n*mu, 1, j, a, b, lam, gamma)` для
      занятых состояний и `abandonment_chain(0.0, 0, n*mu, 0, j, a, b, lam, gamma,
      start_idle=True)` для простаивающих с `j<a-1`.
- [x] `get_w()`/`get_tail()`: добавлена `gamma`-ветка (`_get_w_with_abandonment`,
      `_get_tail_with_abandonment`), условные на «обслужена», как в EPIC-068.
- [x] Регрессия `gamma=0` → точное совпадение с EPIC-069 (`rtol=1e-9`).
- [x] Независимая DES-валидация (`gamma>0`, несколько `(a,b,n)`) —
      `tests/units/test_bulk_service_multiserver_abandonment.py`, 10 тестов.
- [x] Тесты, pylint 10/10, black/isort чисты; полный набор (1892 теста) проходит.
- [x] Документация: docstring модуля, `docs/models/batch.{md,ru.md}`.
- [ ] Численный пример для статьи 2 (одноканальная/многоканальная split) — нетерпение
      в перегруженном GPU-пуле — отложен до физического разделения статьи.

## Что по-прежнему НЕ входит в объём

- Батч-размер-зависимое `mu(size)` для `n>1` — отдельный, заметно более сложный резерв
  (EPIC-072, полный вектор занятости внутри поглощающей цепи).
- H2-обслуживание для `n>1` — тоже отдельный резерв (ветвящаяся структура, EPIC-072).
- H2 + нетерпение для `n=1` (EPIC-071) — другая комбинация, не затрагивается здесь.

## Критерии готовности (DoD эпика)

Общий [DoD](../DOD.md). Обязательно: `gamma=0` точная регрессия к EPIC-069; `gamma>0`
независимая DES-валидация; полный набор тестов проходит; pylint/black/isort чисты.

## Результаты

Подтвердилась предварительная оценка риска: комбинация реализована без новой
теоретической конструкции, переиспользованием трёх уже провалидированных кусочков
EPIC-068/069 (отток `j*gamma`, `abandonment_chain` с агрегированной ставкой `n*mu`,
формула момента `n+1` применений). Независимый DES подтвердил точность на нескольких
`(a,b,n)`; `gamma=0` точно сводится к EPIC-069. Закрывает первую из трёх резервных
комбинаций, отмеченных в «Ограничениях» статьи batch-service-sla; оставшиеся две
(H2+нетерпение — EPIC-071; несколько каналов + фазовое/batch-size-зависимое
обслуживание — EPIC-072) требуют настоящей новой конструкции состояния и остаются
отдельными эпиками.
