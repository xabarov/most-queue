# EPIC-035: M/G^[a,b]/1 с общим (Erlang-подогнанным) обслуживанием батча

- **Статус:** done
- **Создан:** 2026-09-30
- **Roadmap:** [../roadmaps/bulk_service_general_erlang_roadmap.md](../roadmaps/bulk_service_general_erlang_roadmap.md)

## Цель

Закрыть явно обозначенный резерв EPIC-012 («M/G^[b]/1 через embedded chain») — снять допущение
об экспоненциальности времени обслуживания батча в `BulkServiceMM1Calc`, добавив Erlang(k,rate)
представление (низкий CV<=1, реалистично для предсказуемого времени батч-обработки GPU/LLM).

## Контекст

Обзор литературы: [../research/bulk-service-general-erlang-2026.md](../research/bulk-service-general-erlang-2026.md).
Классический embedded-chain/PGF метод (Neuts 1975, Chaudhry-Templeton) требует
supplementary-variable аргумента для перевода embedded-chain-at-departures распределения в
непрерывное время — сочтено избыточным риском после двух ресурсоёмких эпиков (EDF, admission
control) в этой сессии; выбран более безопасный, уже многократно проверенный в репозитории путь:
подгонка Erlang(k,rate) по моментам + расширение существующей CTMC (batch-in-service, waiting)
фазовым измерением. `k=1` — точная регрессия к уже реализованной модели. По ходу вывода поймана и
исправлена ошибка конвенции ставки фазы (`k*rate` вместо `rate`) — регрессия на `k=1` случайно
совпала, разошлась только на `k=3` против DES, что и выявило проблему.

## Результаты

Реализовано по плану ([roadmap](../roadmaps/bulk_service_general_erlang_roadmap.md)), с
намеренным выбором более низкорискового пути после двух ресурсоёмких эпиков. Кратко:

- **Ядро:** `BulkServiceErlangCalc` — CTMC над `(i, p, j)` (размер батча в обслуживании,
  Erlang-фаза, ожидающие); классический embedded-chain/PGF метод (Neuts 1975,
  Chaudhry-Templeton) сознательно отложен в пользу уже многократно проверенной в репозитории
  техники — подгонка распределения к фазовому семейству по моментам + расширение существующей
  CTMC фазовым измерением (тот же стандарт, что `MaxDistribution`/SLA-слой). `set_servers_from_moments()`
  — подгонка `(k,rate)` по моментам через уже существующий `ErlangDistribution.get_params`.
- **Найденная и исправленная ошибка:** ставка перехода фазы сначала была `k*rate` вместо
  корректной `rate` — ошибка в `k²` раз на среднем. Ошибка была НЕВИДИМА на регрессии `k=1`
  (`k*rate=rate` при k=1 случайно), проявилась только при сравнении `k=3` с независимой DES
  (расхождение ~4×, не шум). Урок: регрессия на вырожденном значении параметра может пройти
  даже при наличии бага, если его эффект обнуляется именно в этой точке — нужна ДОПОЛНИТЕЛЬНАЯ
  проверка на невырожденном значении.
- **Проверка:** `k=1` — точная регрессия к `BulkServiceMM1Calc` (совпадение до `float64`); `k=3`
  (и другие `k`) — против независимой (написанной с нуля) DES; монотонность (больший `k` при
  фиксированном среднем — ниже CV, предсказуемее — не увеличивает `E[V]`).
- **Тесты:** `tests/units/test_bulk_service_erlang.py` — 7 passed. Полный прогон `tests/` —
  **663 passed, 0 failed** (863s), регрессий нет.
- **Документация:** новая подсекция в `docs/models/batch.md`/`.ru.md` (EN+RU), новые строки в
  `docs/models.md`/`.ru.md`.
- **Резерв на будущее:** H2-подгонка (CV≥1); точные моменты (не только среднее) — потребует
  PASTA-конструкцию, учитывающую фазу батча в момент прихода клиента (сложнее, чем в EPIC-032);
  batch-size-зависимые параметры Erlang; полностью общий (не phase-type) embedded-chain/PGF
  метод (Neuts 1975) — при большем бюджете времени.
