# EPIC-066: Точная вероятность нарушения SLA для batch-service очередей

- **Статус:** done
- **Создан:** 2026-10-05
- **Roadmap:** [batch_service_sla_exact_tail_roadmap.md](../roadmaps/batch_service_sla_exact_tail_roadmap.md)
- **Основание:** [batch-service-sla-exact-tail-2026.md](../research/batch-service-sla-exact-tail-2026.md)
  (обзор литературы: Inoue 2021, bulk-service литература 2012-2026, EPIC-021/032 внутренний пробел)

## Цель

Для GPU/LLM-инференса с динамическим батчингом и ограниченным окном `[a,b]` вывести ТОЧНУЮ (не
подогнанную по моментам, не оценку сверху) вероятность нарушения SLA `P(W>D)` и CDF ожидания для
`M/PH^[a,b]/1` при `a=1` (Erlang- и H2-подогнанное батч-время, EPIC-035/036). Это сильнее
опубликованной оценки сверху для среднего (Inoue, *Performance Evaluation*, 2021,
doi:10.1016/j.peva.2020.102183, 24 цитирования) и устраняет явно зафиксированное в EPIC-021
исключение bulk-service из SLA-слоя (`most_queue/theory/utils/sla.py`) новым точным результатом,
а не просто типовым приближением через `fit_from_moments`.

## Контракт до реализации

- Использовать уже существующий phase-type/CTMC аппарат `get_w()` (per-state гипоэкспоненциальная
  декомпозиция `W`), не новую теорию с нуля — хвост через матричную экспоненту сужённого
  генератора, не через ручные частичные дроби (избегает отдельного разбора кратных полюсов и
  ветвления H2).
- Scope — `a=1` (как и для моментов в EPIC-032); `a>1` (idle-refill) — явный резерв.
- Регрессия к `mm1_deadline_violation_prob` (`b=1`, `k=1`/вырожденный H2) — обязательный якорь
  перед утверждением формулы верной.
- DES-кросс-валидация хвоста (не только среднего/моментов) в нескольких точках `t`, `(a,b)`, CV —
  до объявления результата точным.
- Численное сравнение с приближением EPIC-021 (`fit_from_moments`) и с оценкой среднего Inoue
  (2021, для `E[W]` отдельно) — количественная демонстрация цены приближений, часть результата,
  не только демонстрация новой формулы.
- Расширение существующего SLA-слоя (`sla.py`), не замена: остальные калькуляторы остаются на
  приближении через моменты.

## Результаты

Точный `get_tail(t)`/`get_cdf(t)` реализован для всех трёх калькуляторов
(`BulkServiceMM1Calc`, `BulkServiceErlangCalc`, `BulkServiceH2Calc`), `a=1`:
каждое занятое состояние `(i,[p/phase],j)` раскладывает `W` на phase-type
цепь («остаток текущего батча» + `j//b` батчей впереди), точный хвост —
действие матричной экспоненты на эту цепь. Для MM1/Erlang цепь
последовательная (generalized Erlang/Coxian); для H2 — ветвящаяся (каждый
следующий батч заново выбирает фазу), подгенератор строится явно через
разреженную матрицу. Регрессии (`b=1`→`mm1_deadline_violation_prob`,
`k=1`/`p1=1`→`BulkServiceMM1Calc`) совпадают до `~1e-16`; независимая DES
подтверждает все три калькулятора на batch-size-dependent/небазовом CV
сценариях, включая глубокий хвост, где DES даёт 0 событий из 3М выборок, а
точный результат — согласующееся по порядку малое значение.

**Инженерная находка:** первая реализация (плотная `scipy.linalg.expm`)
была практически непригодна (57 с на вызов при `queue_truncation=500`);
переход на `scipy.sparse.linalg.expm_multiply` дал то же значение за 0.19 с
(~300× быстрее) — решающее для практического `queue_truncation`.

**Численное сравнение** (`examples/batch_service_sla_exact_tail_comparison.py`,
детерминированный синтетический расчёт, параметры из fit Inoue 2021 для
Tesla V100 ResNet50): при малом `b_max` (реалистичный предел из-за памяти
GPU) истинная `E[W]` превышает upper bound Inoue (3.353) — до **~10×** при
`b_max=2` и CV=2.0 (35.06 против 3.353); граница, доказанная для
неограниченного батча, не распространяется на ограниченное окно. Отдельно,
приближение SLA-слоя по двум моментам (`fit_from_moments`) переоценивает
`P(W>D)` в глубоком хвосте на порядки (до **+2.7×10⁸%** при `b_max=16, D=20`)
— количественная демонстрация цены приближения именно в режиме, релевантном
GPU/LLM SLA (редкие, но некритично редкие нарушения).

19 новых тестов, полный `pytest tests/ -m "not slow" -n auto` — 1823 passed
(было 1804). pylint `most_queue` без новых замечаний (9.98/10, не
изменился), black/isort чисты.
