# EPIC-039: Queueing-inventory, c гетерогенных серверов с H2-подогнанным обслуживанием

- **Статус:** done
- **Создан:** 2026-09-30
- **Roadmap:** [../roadmaps/queueing_inventory_heterogeneous_servers_h2_service_roadmap.md](../roadmaps/queueing_inventory_heterogeneous_servers_h2_service_roadmap.md)

## Цель

По явной просьбе пользователя сделать обслуживание в queueing-inventory ближе к реальности:
каждый из c гетерогенных серверов (EPIC-038) теперь имеет СВОЁ H2-распределение времени
обслуживания (`p1_k, mu1_k, mu2_k`), а не просто скалярную экспоненциальную ставку.

## Контекст

Обзор: [../research/queueing-inventory-heterogeneous-servers-h2-service-2026.md](../research/queueing-inventory-heterogeneous-servers-h2-service-2026.md).
Комбинация двух уже проверенных техник: H2-фазовое расширение CTMC (EPIC-036) + расщепление на
подмножества для гетерогенных серверов (EPIC-038). Состояние сервера расширено с бинарного
(свободен/занят) до тернарного (свободен / занят-ветвь-0 / занят-ветвь-1) — граница растёт как
`3^c - 2^c`, повторяющаяся часть QBD впервые получает нескалярное фазовое пространство (`2^c`
комбинаций ветвей). H2 выбран вместо Erlang намеренно: ветвь фиксируется один раз при старте
обслуживания и не меняется до ухода — значит, в повторяющейся части QBD нет переходов внутри
уровня, только между уровнями, той же формы, что и в чисто экспоненциальном EPIC-038. Комплексные
H2-параметры (`fit_h2_clx`) НЕ используются — для построения корректной CTMC нужны вещественные
неотрицательные ставки/вероятности; везде в библиотеке для этого применяется `fit_h2` (метод
Алиева). Конструкция провалидирована численным прототипом до написания финального кода: при
`p1_k=1` для всех серверов точно (до float64) сводится к `MMcQueueingInventoryHeterogeneousCalc`
(EPIC-038); общий случай сверен с независимой DES при c=2,3, backorder и lost_sales.

## Результаты

Новый класс `MMcQueueingInventoryHeterogeneousH2Calc`
(`most_queue/theory/inventory/mmc_heterogeneous_h2_inventory.py`) — точная queueing-inventory
система с c гетерогенными серверами, у каждого из которых СВОЁ H2-распределение времени
обслуживания. Состояние каждого сервера расширено с бинарного (EPIC-038: свободен/занят) до
тернарного (свободен / занят-ветвь-0 / занят-ветвь-1). Граница растёт как `3^c - 2^c`
конфигураций; впервые в этой серии эпиков повторяющаяся часть QBD получила нескалярное фазовое
пространство (`2^c` комбинаций ветвей) — но без переходов внутри уровня, благодаря свойству H2
«ветвь выбирается один раз при старте и не меняется». Плюс `MMcQueueingInventoryHeterogeneousH2Sim`
(`most_queue/sim/inventory.py`).

**Важное методологическое решение:** явно НЕ используются комплексные H2-параметры (`fit_h2_clx`)
— по просьбе пользователя про «H2-аппроксимацию с комплексными параметрами» проверил и
задокументировал, почему это невозможно для построения CTMC (ставки/вероятности генератора
обязаны быть вещественными и неотрицательными); используется только `fit_h2` (метод Алиева,
вещественный по построению), та же конвенция, что и в EPIC-036.

**Валидация (без найденных ошибок — численный прототип проверен ДО написания финального кода):**
`p1_k=1` для всех серверов точно (до `1e-9`) воспроизводит `MMcQueueingInventoryHeterogeneousCalc`
(EPIC-038) при c=2,3; общий случай с реально разными H2 на каждом сервере сверен с независимой
DES при c=2,3, оба режима политики (backorder/lost_sales) — совпало в пределах Monte Carlo
допуска.

**Тесты:** 14 новых unit-тестов
(`tests/units/test_mmc_queueing_inventory_heterogeneous_h2.py`) + 2 новых DES cross-validation
теста (`tests/test_inventory.py`). Полный набор тестов: 724 passed, 0 failed (331s,
`pytest tests/ -n auto`).

**Документация:** `docs/models/inventory.md`+`.ru.md` — новая подсекция с явным объяснением,
почему `fit_h2_clx` не используется; `docs/models.md`/`.ru.md` — новая строка.

**Резерв:** Erlang-на-сервер (нужны переходы продвижения фазы внутри уровня — заметно сложнее,
чем H2, по той же причине, почему EPIC-036 оказался проще EPIC-035); смешанные семейства (часть
серверов Erlang, часть H2); фазовое время пополнения склада (более дешёвое расширение, отложено
по явной просьбе пользователя в пользу этого, более сложного); точные моменты выше среднего.
