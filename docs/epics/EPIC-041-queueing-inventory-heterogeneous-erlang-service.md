# EPIC-041: Queueing-inventory, c гетерогенных серверов с Erlang-подогнанным обслуживанием

- **Статус:** done
- **Создан:** 2026-09-30
- **Roadmap:** [../roadmaps/queueing_inventory_heterogeneous_servers_erlang_service_roadmap.md](../roadmaps/queueing_inventory_heterogeneous_servers_erlang_service_roadmap.md)

## Цель

Комплемент EPIC-039 (H2, CV≥1): каждый гетерогенный сервер получает своё Erlang(r_k, rate_k)
(CV≤1) время обслуживания вместо H2.

## Контекст

Обзор: [../research/queueing-inventory-heterogeneous-servers-erlang-service-2026.md](../research/queueing-inventory-heterogeneous-servers-erlang-service-2026.md).
Сложнее, чем EPIC-039: Erlang — последовательная цепочка фаз, требует переходов продвижения
фазы ВНУТРИ уровня повторяющейся части QBD (в отличие от H2, где ветвь фиксируется один раз).
Тот же класс сложности, что дал ошибку k² в EPIC-035 — и действительно, численный прототип нашёл
реальный баг: переиспользованный `diag_block` блокировал ставку продвижения фазы при `i=0` вместе
со ставкой завершения (только последняя фаза должна блокироваться — она расходует запас;
промежуточные продвижения фазы запас не трогают). Пойман на `r_k>1` DES-сверке, НЕ на вырожденном
`r_k=1` (который случайно проходил).

## Результаты

Новый класс `MMcQueueingInventoryHeterogeneousErlangCalc`
(`most_queue/theory/inventory/mmc_heterogeneous_erlang_inventory.py`) — точная queueing-inventory
система с c гетерогенными серверами, у каждого из которых СВОЁ Erlang-распределение времени
обслуживания (комплемент EPIC-039 для CV≤1). Состояние сервера расширено с бинарного до
`(r_k+1)`-значного (свободен / занят-на-фазе-p). Первая модель гетерогенных серверов в этой
серии, где повторяющаяся часть QBD получила переходы ВНУТРИ уровня (продвижение фазы без ухода
клиента) — H2-модели (EPIC-039) это было не нужно.

**Найденная и исправленная ошибка (поймана через НЕвырожденную проверку `r_k>1`, не через
`r_k=1`):** переиспользованный `diag_block` блокировал ставку продвижения фазы при `i=0` вместе
со ставкой завершения обслуживания — но только последняя фаза расходует запас и должна
блокироваться; промежуточные продвижения фазы запас не трогают и блокироваться не должны.
Матрица не проходила проверку «сумма строки = 0», QBD расходился при любом `r_k>1`, `r_k=1`
случайно проходил (там «последняя фаза» = «весь сервер»). Исправлено разделением ставки на
`departure_rate` (блокируется при `i=0`) и `advance_rate` (никогда).

**Валидация:** `r_k=1` для всех серверов точно (до `1e-9`) воспроизводит
`MMcQueueingInventoryHeterogeneousCalc` при c=2,3; общий случай с реально разными `r_k` (тест:
(2,3) и (3,4), ФИКСИРОВАННОЕ среднее, тот же урок что и EPIC-040) сверен с независимой DES при
c=2, оба режима политики — совпало в пределах Monte Carlo допуска.

**Тесты:** 14 новых unit-тестов
(`tests/units/test_mmc_queueing_inventory_heterogeneous_erlang.py`) + 2 новых DES
cross-validation теста (`tests/test_inventory.py`). Полный набор тестов (вместе с EPIC-040/042/043):
769 passed, 0 failed (410s, `pytest tests/ -n auto`).

**Документация:** `docs/models/inventory.md`+`.ru.md` — новая подсекция рядом с H2-подсекцией
EPIC-039 (с явным описанием найденного бага); `docs/models.md`/`.ru.md` — новая строка + обновлена
сводная строка семейства.

**Резерв:** смешанные семейства (часть серверов Erlang, часть H2); фазовое время пополнения
склада для этой модели (EPIC-040 покрывает только базовый M/M/1); точные моменты выше среднего.
