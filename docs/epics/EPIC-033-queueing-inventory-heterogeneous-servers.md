# EPIC-033: Queueing-inventory с двумя гетерогенными серверами

- **Статус:** done
- **Создан:** 2026-09-29
- **Roadmap:** [../roadmaps/queueing_inventory_heterogeneous_servers_roadmap.md](../roadmaps/queueing_inventory_heterogeneous_servers_roadmap.md)

## Цель

Обобщить `MMcQueueingInventoryCalc` (EPIC-028, `c` ОДИНАКОВЫХ серверов) на `c=2` **гетерогенных**
(разноскоростных) сервера, разделяющих общий склад с политикой `(s,S)`, backorder/lost-sales.

## Контекст

Обзор литературы: [../research/queueing-inventory-heterogeneous-servers-2026.md](../research/queueing-inventory-heterogeneous-servers-2026.md).
Прямая комбинация двух уже реализованных техник: расщепление состояний по идентичности занятого
сервера (Krishnamoorthi 1963, EPIC-023/025) + сложенный граничный суперблок для QBD-солвера
(EPIC-028). Ключевая новая деталь — переход `n=2→n=1` должен «расщепляться» по тому, КАКОЙ сервер
освободился (аналогично EPIC-023/025), теперь применительно к переходу `B10` QBD, а не к плоскому
списку переходов CTMC. Прямые прецеденты в литературе — «junior/senior server queueing-inventory»
(2023/2025), хоть и недоступны для чтения полностью — вывод блоков независимый, обоснован через
переиспользование уже проверенных техник репозитория. Масштаб: `c=2` (комбинаторный рост числа
конфигураций при `c>2` — резерв).

## Результаты

Реализовано по плану ([roadmap](../roadmaps/queueing_inventory_heterogeneous_servers_roadmap.md)).
Кратко:

- **Ядро:** `MM2QueueingInventoryHeterogeneousCalc` — механическая комбинация двух уже проверенных
  техник: расщепление состояний (Krishnamoorthi 1963, EPIC-023/025) + сложенный граничный
  суперблок QBD (EPIC-028). Состояние `(n, config, i)`: `config∈{1,2}` различает, какой именно
  сервер занят, нужен только при `n=1`. Граница из ДВУХ качественно разных уровней (`n=0`, `m`
  фаз; `n=1`, `2m` фаз) сложена в суперблок `3m`; новый элемент — расщепление перехода `n=2→n=1`
  по тому, какой сервер освободился (та же техника EPIC-023/025, теперь на уровне блока `B10`
  QBD, а не плоского списка переходов CTMC).
- **Найденная и исправленная ошибка в собственном выводе:** первая версия `get_w()` использовала
  `E[S]=1/(μ1+μ2)` — проверка на `μ1=μ2` сразу показала ошибку (даёт `1/(2μ)` вместо корректного
  `1/μ`, известного из уже проверенного `MMcQueueingInventoryCalc(c=2)`). Исправлено через вывод
  по балансу потоков: `E[S] = (P(сервер1 активно обслуживает) + P(сервер2 активно обслуживает)) /
  λ_эфф`. Пойман аналитически (регрессионной проверкой), до первого прогона DES.
- **Проверка:** точная регрессия к `MMcQueueingInventoryCalc(c=2)` при `μ1=μ2` (совпадение до
  1e-16); малый residual QBD; монотонность (быстрее `μ1` не увеличивает `E[W]`/`stockout_prob`);
  DES кросс-валидация для genuinely гетерогенного случая (обе `policy`, совпадение <1%).
- **Тесты:** `tests/units/test_mm2_queueing_inventory_heterogeneous.py` — 14 passed;
  `tests/test_inventory.py` — 2 новых DES-теста. Полный прогон `tests/` — **642 passed, 0 failed**
  (848s), регрессий нет.
- **Документация:** новая секция «Гетерогенные серверы (c=2)» в `docs/models/inventory.md`/`.ru.md`
  (EN+RU), новые строки в `docs/models.md`/`.ru.md`.
- **Резерв на будущее:** общий `c>2` гетерогенных серверов — комбинаторный рост числа конфигураций
  «кто именно занят» на промежуточных уровнях `n=1,...,c-1`.
