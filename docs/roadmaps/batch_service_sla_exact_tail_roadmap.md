# Roadmap: точный хвост `P(W>D)` для M/PH^[a,b]/1 (a=1)

> Источники и позиционирование — `docs/research/batch-service-sla-exact-tail-2026.md`.
> База: EPIC-032/035-037/042/043 (`most_queue/theory/batch/bulk_service*.py`),
> EPIC-021 (`most_queue/theory/utils/sla.py`).

## 1. Идея

`get_w()` уже раскладывает `W` по состояниям стационарного распределения `pi(i,j)` (i>=1,
занято): `W` = "остаток текущего батча" + `j // b` последующих полных батчей. Это ТОЧНОЕ
phase-type представление (конечная поглощающая цепь Маркова: фазы = шаги до начала обслуживания
помеченной заявки), просто сейчас из него берутся только сырые моменты через `conv_moments`.
У phase-type распределения есть точная замкнутая формула хвоста: `P(W>t) = alpha @ expm(T*t) @ 1`,
где `T` — подгенератор поглощающей цепи, `alpha` — начальное распределение по фазам.

**Почему матричная экспонента, а не частичные дроби.** Прямое разложение хвоста
гипоэкспоненциальной/Coxian суммы на простые дроби корректно, но требует отдельной ветки для
совпадающих ставок (кратные полюса → слагаемые `t^m exp(-rate t)`), что для H2-веток (ветвящийся,
не последовательный, phase-type — каждый следующий полный батч заново выбирает фазу H2) даёт
комбинаторно растущее число случаев. Матричная экспонента небольшой (≤ `queue_truncation/b`-го
порядка) подматрицы — механическая, без ручного разбора случаев, в духе уже использованного в
проекте приёма «canonicalize-based построение CTMC избегает ошибок ручного вывода» (EPIC-025).

## 2. Конструкция (для a=1)

Для состояния `(i,j)`, `i>=1`: подматрица `T_{(i,j)}` и вектор `alpha_{(i,j)}` — это СУЖЕНИЕ уже
построенного генератора занятых состояний на переходы «фаза текущего батча продвигается» /
«батч завершается → начинается следующий» (транзакции из-за новых arrivals ОТБРАСЫВАЮТСЯ: они не
меняют, сколько шагов обслуживания осталось ДО уже стоящей в очереди помеченной заявки).
Поглощение — момент, когда обслуживание доходит до позиции помеченной заявки (после `j//b`
полных батчей и текущего остатка). Итоговый точный хвост:

```
P(W > t) = sum_{(i,j): i>=1} pi(i,j) * [alpha_{(i,j)} @ expm(T_{(i,j)} * t) @ ones]
```

Вместо пересчёта отдельной небольшой матричной экспоненты на каждое `(i,j)` (их может быть сотни)
эффективнее собрать ОДНУ объединённую поглощающую цепь, переиспользуя уже построенные индексы фаз
исходного CTMC (прямое сужение общего генератора `Q`, без arrival-переходов, с начальным вектором,
полученным из `pi`) — конкретную инженерию уточнить при реализации, выбор между «много маленьких
expm» и «одна большая» — по факту замера производительности на `queue_truncation`.

## 3. План по классам (в порядке возрастания сложности)

1. **`BulkServiceMM1Calc.get_tail(t)` / `.get_cdf(t)`** — chain чисто последовательный
   (Exp(mu(i)) -> `j//b` раз Exp(mu(b))), регрессионный якорь: при `b=1` обязан точно совпасть с
   уже проверенным `mm1_deadline_violation_prob` (M/M/1 FCFS, `a=b=1` — вырождение batch-service в
   обычный M/M/1).
2. **`BulkServiceErlangCalc`** — тоже последовательная цепь (остаток `(k-p)` фаз текущего батча +
   `(j//b)*k` фаз последующих), регрессия к п.1 при `k=1`.
3. **`BulkServiceH2Calc`** — ветвящаяся (каждый следующий полный батч заново выбирает фазу H2 с
   вероятностью `p1`/`1-p1`) — первый случай, где матричный подход обязателен, не просто удобен.

Каждый шаг — независимая DES-кросс-валидация (эмпирическая `P(W>t)` по большой выборке, сравнение
в нескольких точках `t` и при нескольких `a,b,k`/H2-параметрах) ДО утверждения формулы правильной.

## 4. Связь с EPIC-021 и численное сравнение

- Подключить `get_tail`/`get_cdf` к общему контракту SLA-слоя (`deadline_violation_prob`-подобный
  вызов), пометив как ТОЧНЫЙ (не fitted) путь — расширение, а не замена `sla.py` (остальные
  калькуляторы остаются на приближении через моменты).
- Количественно сравнить на одном и том же сценарии: (а) наш точный `P(W>D)`, (б) приближение
  `sla.fit_from_moments` по тем же сырым моментам `get_w()`, (в) оценку среднего Inoue (2021) как
  верхнюю границу для `E[W]` (не для хвоста — другая величина, сравнение корректно только для
  среднего). Явно указать, при каких `a,b,k,CV` приближение (б) заметно расходится с точным (а) —
  это самостоятельный результат статьи, не просто демонстрация «у нас тоже есть формула».

## 5. Тесты и DoD

- Регрессия `b=1` → `mm1_deadline_violation_prob` (все три класса, `k=1`/`p1` вырожденные).
- DES кросс-валидация хвоста в нескольких точках `t`, нескольких `(a,b)`, нескольких CV (Erlang
  `k=2,5`; H2 `CV=1.5,3`).
- Монотонность: хвост убывает по `t`; `P(W>0)` = `1 - P(simplex idle)` (совпадает с `1 - pi(i=0)`
  при `t→0+` с учётом атома в нуле при простое).
- Полный/быстрый `pytest`, pylint/black/isort, как во всех предыдущих эпиках.

## 6. Резерв

- `a>1` (idle-refill) — остаётся открытым, как и для моментов (EPIC-032).
- Переменная длина генерации токенов в батче (continuous batching) — отдельный будущий эпик,
  нужен отдельный обзор литературы перед оценкой трактуемости.
