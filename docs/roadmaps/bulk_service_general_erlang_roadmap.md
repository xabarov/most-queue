# Roadmap: M/G^[a,b]/1 с общим (Erlang-подогнанным) обслуживанием батча

> Источники и найденная/исправленная ошибка — `docs/research/bulk-service-general-erlang-2026.md`.
> База: EPIC-012/032 (`most_queue/theory/batch/bulk_service.py::BulkServiceMM1Calc`).

## 1. Состояние

`(i, p, j)`: `i` — размер батча в обслуживании (0..b, 0=простой), `p` — текущая фаза Erlang(k,rate)
(0..k-1, значима только при `i>=1`), `j` — число ожидающих. Индексация без «мёртвых» состояний
(отдельно idle-блок `j=0..N` и busy-блок `(i,p,j)` для `i=1..b`, `p=0..k-1`, `j=0..N` — иначе
матрица вырождается: неиспользуемые состояния `(i=0,p>0)` дают пустые строки и сингулярность).

## 2. Переходы

```
idle (j):        arrival (λ): j+1<a  -> idle(j+1)
                                j+1==a -> busy(a, phase=0, j=0)   [батч стартует сразу при достижении порога]

busy (i,p,j):     arrival (λ): j<N -> busy(i,p,j+1)               [просто ставится в очередь]
                   фаза (rate=rate, per-phase, НЕ k*rate — см. §3): p<k-1 -> busy(i,p+1,j)
                   завершение батча (rate=rate, из последней фазы p=k-1):
                       j>=a: -> busy(min(b,j), phase=0, j-min(b,j))   [новый батч стартует сразу]
                       j<a:  -> idle(j)                                [сервер простаивает]
```

## 3. Найденная и исправленная ошибка — конвенция ставки фазы

Первая версия использовала ставку перехода между фазами `k*rate` (перепутав с конвенцией «общая
ставка на k фаз»), что даёт среднее `1/rate` вместо ожидаемого `k/rate` для Erlang(k,rate) — ошибка
в `k²` раз на среднем. Поймано регрессией `k=1` (должна точно совпадать с уже проверенной
`BulkServiceMM1Calc`) — совпала случайно при `k=1` (т.к. `k*rate=rate` при k=1), но `k=3` разошлась
с независимой DES на порядок (DES E[V]≈3.51, ошибочная теория≈0.91). Исправлено: ставка фазы =
`rate` (без множителя k), после чего `k=3` точно совпала с DES (≈3.51 против 3.506–3.525 по трём
сидам).

## 4. Проверка

- **`k=1` → точная регрессия к `BulkServiceMM1Calc`** (совпадение до `float64`-точности,
  1.0293216473192264 vs 1.0293216473192266) — основной regression-тест.
- **`k=3` vs независимая DES** (сэмплирует `rng.gamma(k, 1/rate)` для времени батча) — совпадение
  в пределах MC-погрешности.

## 5. API

```python
class BulkServiceErlangCalc(BaseQueue):
    def __init__(self, a: int, b: int, k: int, queue_truncation: int = 300): ...
    def set_sources(self, l: float): ...
    def set_servers(self, rate: float): ...  # per-phase rate; total mean batch service = k/rate
    def run(self) -> QueueResults: ...        # mean v, w (Little's law, как в исходном EPIC-012)
```

`k` — целое число фаз Erlang (CV = 1/sqrt(k) <= 1). Для подгонки по МОМЕНТАМ (не напрямую `k,rate`)
— добавить classmethod/helper, переиспользующий `ErlangDistribution.get_params(moments)` (уже есть
в библиотеке) для вычисления `k` (округляется до целого) и `rate` из заданных `[mean, m2]`.

## 6. Резерв

- H2-подгонка (CV>=1) — нужна двухветочная структура фаз, не line-Erlang.
- Точные моменты (не только среднее) для этого класса — по аналогии с EPIC-032, но сложнее
  из-за фазовой структуры (PASTA-конструкция должна учитывать, в какой фазе застаёт клиент батч).
- batch-size-зависимые параметры Erlang (сейчас — одно `(k,rate)` для всех размеров батча, как в
  EPIC-012 до появления `mu(size)` callable).
- Классический embedded-chain/PGF метод (Neuts 1975) для ПОЛНОСТЬЮ общего (не phase-type)
  распределения — сложнее конвертировать embedded-chain-at-departures в непрерывное время без
  supplementary-variable аргумента; оставлено на будущее при большем бюджете.
