# Roadmap: M/H2^[a,b]/1 с H2-подогнанным обслуживанием батча (CV≥1)

> Источники и сравнение с Erlang-случаем — `docs/research/bulk-service-general-h2-2026.md`.
> База: EPIC-012/032/035 (`most_queue/theory/batch/`).

## 1. Состояние

`(i, phase, j)`: `i` — размер батча в обслуживании (0..b), `phase ∈ {0,1}` — какая из двух
экспоненциальных ветвей H2 выбрана для ТЕКУЩЕГО батча (значима только при `i>=1`, фиксируется
один раз при СТАРТЕ батча — не меняется до завершения, в отличие от Erlang-фаз, которые
последовательно продвигаются), `j` — число ожидающих.

## 2. Переходы

```
idle (j):        arrival (λ): j+1<a -> idle(j+1)
                                j+1==a -> РАСЩЕПЛЕНИЕ: busy(a,phase=0,0) со ставкой λ·p1
                                                        busy(a,phase=1,0) со ставкой λ·p2

busy (i,phase,j): arrival (λ, j<N): -> busy(i,phase,j+1)
                   завершение батча (ставка mu_phase):
                       j>=a: РАСЩЕПЛЕНИЕ: busy(min(b,j),phase=0,j-min(b,j)) со ставкой mu_phase·p1
                                          busy(min(b,j),phase=1,j-min(b,j)) со ставкой mu_phase·p2
                       j<a:  -> idle(j)   [без расщепления — сервер просто простаивает]
```

Отличие от Erlang (EPIC-035): H2 — «ветвление» (фаза выбирается ОДИН РАЗ при старте батча и
остаётся до конца), а не «цепочка» последовательных фаз. Каждый переход «батч стартует» (из
простоя по порогу ИЛИ сразу после завершения предыдущего батча) расщепляется на ДВЕ взвешенные
подставки (`×p1`, `×p2`) вместо единственного детерминированного перехода в фазу 0.

## 3. Проверка

- **`p1→1` (H2 вырождается в `Exp(mu1)`) → точная регрессия к `BulkServiceMM1Calc`** — совпадение
  до `float64`-точности (`1.0293216473192262` vs `1.0293216473192266`).
- **Общий (двухфазный) случай — против независимой DES** с первой попытки совпало (в отличие от
  Erlang-случая, где была найдена и исправлена ошибка `k²`) — вероятно, потому что «выбор фазы
  один раз при старте» проще корректно закодировать, чем «последовательное продвижение фазы».

## 4. API

```python
class BulkServiceH2Calc(BaseQueue):
    def __init__(self, a: int, b: int, queue_truncation: int = 300): ...
    def set_sources(self, l: float): ...
    def set_servers(self, p1: float, mu1: float, mu2: float): ...
    def set_servers_from_moments(self, moments: list[float]): ...  # H2Distribution.get_params (fit_h2, Aliev's method)
    def run(self) -> QueueResults: ...  # mean v, w
```

`set_servers_from_moments` требует `moments` c CV>=1 (иначе `fit_h2` — см. `most_queue.random.utils.fit`
— либо вырождается в одно-фазное распределение, либо кидает ошибку; та же осторожность, что уже
задокументирована в `theory.utils.sla.fit_from_moments` про `family="h2"`).

## 5. Резерв

- Точные моменты (не только среднее) — как и для Erlang, нужна PASTA-конструкция, учитывающая
  фазу батча в момент прихода клиента.
- batch-size-зависимые параметры H2.
- Единый диспетчер `set_servers_from_moments` с авто-выбором Erlang/H2 по CV (как
  `theory.utils.sla.fit_from_moments(family="auto")`) поверх ОБОИХ классов (`BulkServiceErlangCalc`,
  `BulkServiceH2Calc`) — сейчас выбор семейства вручную вызывающим кодом по CV своего распределения.
