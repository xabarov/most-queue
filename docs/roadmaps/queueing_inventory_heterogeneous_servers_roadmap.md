# Roadmap: queueing-inventory с двумя гетерогенными серверами (c=2)

> Источники — `docs/research/queueing-inventory-heterogeneous-servers-2026.md`. База: EPIC-023/025
> (расщепление состояний, Krishnamoorthi), EPIC-024/026/027/028 (QBD queueing-inventory стек).

## 1. Состояние

`(n, config, i)`: `n` — число клиентов, `i` — уровень запаса (`0..S`), `config ∈ {1,2}` — какой
именно сервер занят, нужен только при `n=1` (при `n=0` никто не занят, при `n>=2` заняты оба —
однозначно). Блокировка обслуживания при `i=0` — как во всём семействе queueing-inventory
(EPIC-024+): единица запаса расходуется В МОМЕНТ завершения обслуживания, не резервируется при
старте.

## 2. Блоки QBD

`m = S+1` (фазы — уровень запаса). Три «уровня» `n`:

- **`n=0`** (никто не занят): фаза = `i`, размерность `m`.
- **`n=1`** (один сервер занят): фаза = `(config, i)`, размерность `2m`.
- **`n>=2`** (оба заняты): фаза = `i`, размерность `m` — однородная повторяющаяся часть QBD.

Граничный суперблок (по аналогии со «стеком» из EPIC-028, но теперь стекуются КАЧЕСТВЕННО разные
уровни, не `c` копий одного): `B00` размерности `m + 2m = 3m` (блоки `n=0` и `n=1` вместе).

### Повторяющаяся часть (n>=2), `μ = μ1+μ2`

Ровно формулы `MMcQueueingInventoryCalc` (EPIC-028) с `c·μ → μ1+μ2`:

```
A0[i,i] = λ                          (A0[0,0]=0 при lost_sales)
A2[i,i-1] = μ1+μ2                     для i=1..S   (A2[0,:]=0 — блокировка при i=0)
A1[i,S] = θ                           для i=0..s
A1[0,0] = -θ (lost) / -(λ+θ) (backorder)
A1[i,i] = -(λ+μ1+μ2+θ)                для i=1..s
A1[i,i] = -(λ+μ1+μ2)                  для i=s+1..S
```

### Граница: n=0 (диагональный блок `D0`, `m×m`)

Как `MM1QueueingInventoryCalc` при `n=0` (никто не обслуживается):

```
D0[i,S] += θ   для i=0..s
D0[0,0] = -θ (lost) / -(λ+θ) (backorder)
D0[i,i] = -(λ+θ)   для i=1..s
D0[i,i] = -λ        для i=s+1..S
```

### Граница: n=1 (блок `2m×2m`, подблоки по `config c∈{1,2}`)

Для каждого `config=c`, локальная диагональ (та же формула, но `μ→μ_c`, т.к. занят только один
сервер):

```
D1[c][i,S] += θ   для i=0..s
D1[c][0,0] = -θ (lost) / -(λ+θ) (backorder)
D1[c][i,i] = -(λ+μ_c+θ)   для i=1..s
D1[c][i,i] = -(λ+μ_c)      для i=s+1..S
```

Уход обслуживания (`n=1→n=0`): подблок `D1[c]` → `n=0`-блок, `i→i-1` при `i>=1`, ставка `μ_c`
(это межуровневый переход внутри границы — часть `B00`, не `A2`).

### Переходы между границей и однородной частью

- `B01` (`n=1 → n=2`, т.е. граница → первый повторяющийся уровень): приход `λ` (или 0 при
  `i=0` и lost_sales) из КАЖДОГО `config`-подблока `n=1`, фаза `i` не меняется (второй клиент
  занимает свободный сервер — переход однозначен, куда бы ни попал).
- `B10` (`n=2 → n=1`, первый повторяющийся уровень → граница) — **расщепление по тому, кто
  освободился** (точно как в EPIC-023/025):
  ```
  rate μ1, i→i-1  ->  B10 в подблок config=2   (сервер 1 освободился, сервер 2 — выживший)
  rate μ2, i→i-1  ->  B10 в подблок config=1   (сервер 2 освободился, сервер 1 — выживший)
  ```
- `B01` от `n=0` уровня (`n=0→n=1`): приход `λ` (или 0 при `i=0`, lost_sales), фаза `i` не
  меняется, попадает в `config=1` (конвенция: первый свободный сервер — сервер 1; если нужен
  конкретный приоритет «сначала быстрый», пометьте более быстрый сервер как сервер 1).

## 3. Проверка на μ1=μ2 → MMcQueueingInventoryCalc(c=2)

При `μ1=μ2=μ`: суперблок `n=1` (`config=1` и `config=2` подблоки идентичны по локальной динамике)
и переходы `B10`/`B01` должны в точности воспроизвести уже реализованный `MMcQueueingInventoryCalc`
(EPIC-028) при `c=2` — **основной регрессионный тест**, аналогично прошлым эпикам семейства
(проверка на «частный случай уже реализованной модели» перед принятием на веру).

## 4. API

```python
class MM2QueueingInventoryHeterogeneousCalc(BaseQueue):
    def __init__(self, s_max: int, s: int = 0, policy: Policy = "backorder",
                 calc_params: CalcParams | None = None): ...
    def set_sources(self, l: float): ...
    def set_servers(self, mu1: float, mu2: float, theta: float): ...
```

Валидация: `s_max>=1`, `0<=s<s_max`, `policy` как раньше, `mu1,mu2,theta>0`. Устойчивость:
`ρ=λ/(μ1+μ2)<1` (необходимо, не достаточно — та же оговорка, что и в EPIC-028, при медленном
пополнении).
