# Roadmap: EDF (Earliest Deadline First) scheduling discipline

> Источники и разбор двух отвергнутых гипотез — `docs/research/edf-scheduling-2026.md`.

## 1. Почему не точный калькулятор, а DES + инвариант

Точный конечномерный анализ EDF (даже 2 класса, экспоненциальные дедлайны) требует, вообще говоря,
отслеживания ПОЛНОГО отсортированного списка дедлайнов в очереди, а не просто счётчиков — это
подтверждено и независимо в литературе (только heavy-traffic/fluid-результаты), и двумя проверенными
и отвергнутыми гипотезами (research-доку §"Rejected hypotheses"). Поэтому эпик даёт:

1. DES-симулятор — точный «по построению» (дисциплина обслуживания реализована буквально, не
   аппроксимирована).
2. Один СТРОГО точный инвариант (закон сохранения работы) — не аппроксимация, используется как
   regression-тест на выходе DES.
3. Композиция с уже готовым SLA-слоем (EPIC-021) — вероятность нарушения дедлайна на класс, из
   оценённых по DES моментов ожидания.

## 2. Закон сохранения работы — точен только при пренебрежимо малом reneging

Для `K` классов, M/M/1 (или M/G/1) с общим сервером и `ρ = Σ ρ_k < 1`:

```
Σ_k ρ_k · E[W_k] = ρ · E0 / (1 - ρ),   E0 = Σ_k λ_k · E[S_k²] / 2
```

Классический результат Kleinrock — но **не выполняется точно** в общем случае для EDF с reneging:
численно проверено (research-дока §"Rejected hypotheses" п.3) — при заметном `miss_prob` (~20%)
отношение LHS/RHS ≈ 0.35, даже после подстановки эффективной (обслуженной, а не поступившей)
интенсивности. Причина: доказательство инвариантности «суммарной недоделанной работы» относительно
дисциплины предполагает, что КАЖДАЯ поступившая заявка в итоге потребляет свой полный объём
обслуживания; reneging убирает ещё не начатое обслуживание заявки как «отрицательный скачок»,
вероятность которого сама зависит от дисциплины (заявка может уйти по reneging при FCFS, но успеть
обслужиться при EDF) — это ломает сам аргумент инвариантности, а не только арифметику. Проверено
повторно с пренебрежимо редким reneging (`miss_prob<0.002`): отношение LHS/RHS стремится к 1
(`0.90` при `miss_prob≈1%`, `0.97` при `miss_prob≈0.1%`) — закон асимптотически верен в пределе
без reneging, что подтверждает корректность самого симулятора (не заявленного инварианта).

**Итог:** используем закон сохранения как regression-тест ТОЛЬКО в конфигурации с редким reneging
(щедрые дедлайны, `miss_prob` близко к 0) — валидирует базовую бухгалтерию времени
ожидания/обслуживания в DES. Для содержательного (lossy) режима, где EDF реально интересен,
кросс-проверка — через сравнение EDF vs FCFS на одних и тех же параметрах (см. §5,
`PriorityQueueSimulator(prty_type="No")`), не через инвариант.

## 3. API

```python
class EDFQueueSim(BaseSimulationCore):
    def __init__(self, n_classes: int, seed: int | None = None): ...
    def set_sources(self, l: list[float]): ...  # per-class Poisson rate
    def set_servers(self, b: list[dict]): ...    # per-class service spec (Kendall), shared server
    def set_deadlines(self, deadlines: list[dict]): ...  # per-class deadline-offset spec (Kendall)
    def run(self, total_served: int, warmup_fraction=0.05) -> EDFResults: ...
```

`deadlines[k]` использует ту же нотацию Кендалла, что и `set_sources`/`set_servers`
(`create_distribution`), так что дедлайн может быть детерминированным (`{"type":"D","params":[d]}`)
или случайным (`{"type":"M","params":[theta]}` и т.д.) — оба случая из research-доки поддержаны без
дополнительной сложности на стороне DES (в отличие от точной теории, где детерминированные и
экспоненциальные дедлайны ведут себя качественно по-разному).

Дисциплина: неприоритетный (single) сервер, при освобождении выбирается ожидающая заявка с
наименьшим АБСОЛЮТНЫМ дедлайном (`arrival_time + D`); заявка, чей дедлайн наступил раньше начала
обслуживания, покидает систему необслуженной (аналог reneging/impatience).

Результат (`EDFResults`): per-class `w` (моменты времени ожидания ОБСЛУЖЕННЫХ заявок), `v` (момент
пребывания), `miss_prob` (доля заявок класса, не успевших к дедлайну), `utilization`.

## 4. Композиция с EPIC-021 SLA-слоем

```python
from most_queue.theory.utils.sla import deadline_violation_prob

p_violation_k = deadline_violation_prob(res.w[k], deadline_k)
```

где `deadline_k` — среднее/константное значение дедлайна класса `k` (для сравнения с `miss_prob`,
посчитанным DES напрямую по факту "истёк раньше начала обслуживания" — два независимых способа
оценить схожую, но не тождественную величину: `miss_prob` учитывает reneging до НАЧАЛА
обслуживания, `deadline_violation_prob` от `sla.py` — вероятность превышения дедлайна временем
ОЖИДАНИЯ у уже посчитанного распределения; для детерминированного дедлайна и non-reneging варианта
эпика (заявки не покидают очередь, только считается, уложились ли) они должны совпадать в пределах
точности fit — полезный кросс-чек).

## 7. Резерв

- Точный closed-form/series калькулятор среднего ожидания для 2-класcового delayed-APQ (Mojalal,
  Stanford, Taylor, Ziedins) — требует восстановления формул из paywalled источников или
  переоткрытия через conservation law + Laplace-преобразования.
- Многоканальный EDF (`M/M/c`).
- Preemptive EDF (заявка прерывается, если появляется более срочная).
