# Admission control по дедлайну

[🇬🇧 English version](admission-control.md) · [← Каталог моделей](../models.ru.md)

**Простыми словами:** у запроса есть SLO — «я полезен, только если ответ придёт примерно за это
время». Вместо того чтобы всегда ставить всех в очередь FCFS и надеяться ([SLA-слой](sla.ru.md)),
или переупорядочивать обслуживание по срочности ([EDF](edf.ru.md)), эта модель принимает
ПРОАКТИВНОЕ решение принять/отклонить в момент прихода заявки: если её собственный (случайный)
дедлайн уже неосуществим при текущей загрузке — отклонить немедленно, вообще не ставя в очередь, а
среди принятых сохранять FCFS-порядок. Это третий, качественно отдельный механизм управления SLO
в этом каталоге.

### M/M/1 с дедлайном Exp(θ) — точно, через сходящийся ряд

**Описание:** пуассоновский приход (`λ`), экспоненциальное обслуживание (`μ`), FCFS-порядок
сохраняется. Каждая приходящая заявка тянет свой относительный дедлайн `D ~ Exp(θ)` и наблюдает
текущую загрузку (virtual waiting time) `U`, с которой бы столкнулась; принимается тогда и только
тогда, когда `D > U`, иначе отклоняется немедленно. Решается точно через классическое
level-crossing (в духе Takács) функциональное уравнение для преобразования Лапласа-Стилтьеса
загрузки `φ(s) = E[e^{-sU}]`:

```
φ(s) = π₀ + [λ/(s+μ)] · φ(s+θ)
```

Поскольку дедлайн экспоненциальный, это сворачивается в быстро сходящийся ряд (система ВСЕГДА
устойчива, независимо от `λ`, т.к. приходы при большой загрузке автоматически отклоняются):

```
φ(s) = π₀ · Σ_{n=0}^∞ λⁿ / Π_{j=0}^{n-1}(s + jθ + μ)
```

вычисляется через точную арифметику усечённых степенных рядов (Тейлора) вокруг `s=0` — НЕ через
конечные разности — чтобы получить точные моменты без ошибки численного дифференцирования.
`loss_prob = 1 - φ(θ)`; моменты времени пребывания ПРИНЯТОЙ заявки используют ту же технику
применительно к `φ(s+θ)` (делённую на `φ(θ)`, вероятность приёма) — чтобы корректно учесть, что
приём СМЕЩАЕТ наблюдаемую загрузку в сторону меньших значений.

**Неверный «короткий путь», пойманный до сдачи в репо (задокументирован, чтобы никто не выводил
его заново):** первая, гораздо более простая на вид гипотеза — раз обслуживание M/M/1
памяти-less, считать число в системе `n` достаточной статистикой и построить цепь
рождения-гибели с зависящей от состояния интенсивностью, `P(admit|n) = (μ/(μ+θ))ⁿ` — НЕВЕРНА. Сама
формула верна изолированно, но `n` здесь НЕ достаточная статистика: обусловливание на факте
«приём произошёл» смещает загрузку через хвостовую функцию дедлайна, и — в отличие от обычного
обусловливания на времени с последнего перехода — это смещение НЕ стирается памятью-less
свойством обслуживания. Поймано через тщательную DES-симуляцию, показавшую небольшое, устойчивое
по сидам, растущее с `n` расхождение с предсказанием короткого пути. См.
[`docs/research/llm-serving-deadline-admission-control-2026.md`](../research/llm-serving-deadline-admission-control-2026.md)
для полных численных доказательств.

**Класс расчёта:** `MM1DeadlineAdmissionControlCalc` (`most_queue.theory.admission_control`)
**Симуляция:** `MM1DeadlineAdmissionControlSim` (`most_queue.sim.admission_control`)

```python
from most_queue.theory.admission_control import MM1DeadlineAdmissionControlCalc

calc = MM1DeadlineAdmissionControlCalc()
calc.set_sources(l=1.2)
calc.set_servers(mu=1.0)
calc.set_deadline(theta=0.5)   # D ~ Exp(theta)
res = calc.run()
# res.v, res.w -- моменты пребывания/ожидания ПРИНЯТЫХ заявок (отклонённые не входят)
# res.loss_prob -- P(приходящая заявка отклонена немедленно)
```

### Точность и охват

Точно (сходящийся ряд, не аппроксимация) для дедлайна `Exp(θ)`. **Не покрыто (резерв):** общие
(не экспоненциальные) распределения дедлайна — трюк со сворачиванием ряда специфично использует
постоянное отношение хвоста экспоненты; общее `G` потребовало бы другой численный метод (напр.
прямая дискретизация лежащего в основе интегрального уравнения Вольтерра). Многоканальный (`c>1`)
admission control также не покрыт.

**См. также:** [SLA / вероятность нарушения дедлайна](sla.ru.md) (пассивный, пост-hoc, любая
дисциплина) и [EDF](edf.ru.md) (переупорядочивает обслуживание вместо отклонения) — два других
механизма управления SLO в этом каталоге, у каждого свой компромисс точность/охват.
