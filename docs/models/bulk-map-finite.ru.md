# Групповое обслуживание с коррелированным входом и конечным буфером: MAP/PH^(a,b)/1/N

[🇬🇧 English version](bulk-map-finite.md) · [← Каталог моделей](../models.ru.md)

**Суть:** один прибор обслуживает заявки группами по общему правилу `(a, b)` — ждёт, пока
накопится `a` заявок, затем берёт сразу до `b` штук, — поток приходов **пачечный**, а не
пуассоновский, а накопитель конечен, так что заявка, заставшая его полным, теряется. Интересует
всё распределение времени ожидания принятой заявки, а не только его среднее.

От остального семейства [группового обслуживания](batch.ru.md) эту страницу отличают две вещи.
Приходы задаются **марковским потоком (MAP)**, то есть могут быть коррелированы во времени — а это
и есть реалистичный случай для потока запросов, который приходит всплесками. И буфер действительно
**конечен**, так что блокировка входит в модель, а не является численным усечением.

### Модель

Приходы — MAP `(D0, D1)`. Буфер вмещает не более `N` **ожидающих** заявок; обслуживаемая группа
его не занимает, а заявка, заставшая `N` ожидающих, теряется. Прибор забирает `min(очередь, b)`
заявок, как только их набралось не менее `a`, а время обслуживания группы имеет фазовое
распределение `(β, S)` — одно и то же при любом размере группы. Вся группа уходит одновременно по
её завершении, поэтому

```
время пребывания = время ожидания + одно полное обслуживание группы
```

причём слагаемые независимы: группа, в которую попадает заявка, к моменту окончания её ожидания
ещё не начиналась.

### Точное распределение без обращения преобразований

**Класс:** `BulkServiceMapPhCalc` (`most_queue.theory.batch.map_ph_finite_buffer`)

```python
import numpy as np
from most_queue.random.map_ph import MAPParams, PHParams
from most_queue.theory.batch.map_ph_finite_buffer import BulkServiceMapPhCalc

calc = BulkServiceMapPhCalc(a=3, b=8, capacity=25)
calc.set_sources(MAPParams(D0=np.array([[-9.0, 0.6], [0.4, -1.4]]),
                           D1=np.array([[8.0, 0.4], [0.2, 0.8]])))
calc.set_servers(PHParams(alpha=np.array([0.3, 0.7]),
                          T=np.array([[-2.0, 1.0], [0.0, -5.0]])))

calc.get_w(2)                      # точные начальные моменты времени ожидания
calc.get_w_cdf([0.5, 1.0, 2.0])    # точная функция распределения, в одной точке или сразу во многих
calc.get_v_cdf(1.0)                # время пребывания
calc.get_loss_probability()
calc.run()                         # всё сразу, вместе с вероятностями состояний
```

Для классического пуассоновского случая есть сокращения: `set_poisson_sources(6.7)` и
`set_exponential_servers(1.7)`.

**Метод.** Модель принадлежит работе Banik A.D., Chaudhry M.L., Barik S., Singh G., *On the
Heuristic Computational Procedures of the Virtual Waiting-Time Distribution in a Non-renewal Input
Finite-Buffer Bulk-Service Queues: MAP/R^(a,b)/1/N*, J. Indian Soc. Probab. Stat. 26 (2025)
585–630, [doi:10.1007/s41096-025-00232-0](https://doi.org/10.1007/s41096-025-00232-0), а для
пуассоновского случая — её открытой предшественнице Chaudhry M.L., Banik A.D., Barik S.,
Goswami V., *A Novel Computational Procedure for the Waiting-Time Distribution (In the Queue) for
Bulk-Service Finite-Buffer Queues with Poisson Input*, Mathematics 11(5) (2023) 1142,
[doi:10.3390/math11051142](https://doi.org/10.3390/math11051142). **Модель принадлежит авторам.**

Отличается путь. Обе статьи идут к времени ожидания через преобразования: распределение длины
очереди даёт производящую функцию, функциональное соотношение переводит её в преобразование
Лапласа–Стилтьеса времени ожидания, и это преобразование обращается численно. Само преобразование
точно и элементарно — формула (39) статьи 2023 года есть конечная сумма степеней `(1 − s/λ')`.
Приближение живёт именно в **обращении**: авторы подгоняют к нему рациональную функцию по Паде
(командой `pade` в Maple) и раскладывают на простейшие дроби. Статья 2025 года по той же причине
называет свои процедуры эвристическими прямо в заглавии.

Здесь преобразование не строится вовсе, так что обращать нечего. Реализация прослеживает
**помеченную заявку** по поглощающей марковской цепи и считывает время ожидания напрямую как
фазовое распределение: `1 − α exp(T t) 1` для функции распределения, `k! α (−T)^−k 1` для
моментов. Точно до машинной погрешности, без шага Паде и без допуска обращения, который надо
подбирать.

**Почему цепь остаётся небольшой.** Проследим за заявкой, вставшей на позицию `p`. При каждом
завершении обслуживания прибор забирает ровно `b` заявок с начала очереди, если их там больше `b`,
так что `p` уменьшается на `b`, и больше ничто не важно: если `p > b`, то в очереди не меньше
`p > b ≥ a`, и следующая группа заведомо начнётся. Длина очереди играет роль ровно один раз — на
том завершении, где `p ≤ b`, чтобы решить, начнёт ли прибор сразу или будет простаивать, пока не
наберётся `a`. А для **этой** проверки число заявок **позади** помеченной нужно знать лишь до
`a − 1`: при большем очередь заведомо достаточно длинна. Поэтому цепь индексируется позицией и
счётчиком, ограниченным сверху `a`, и её размер — `O(N·a·m_s·m_a)`, а не `O(N²·m_s·m_a)`.

### Во что обходится обращение преобразования

В двух местах, и оба — следствие одного и того же шага; к каждому расхождению привлечён
независимый арбитр.

**Второй момент.** В таблице 6 статьи 2023 года для одной и той же величины напечатаны два
значения: `E(Vq²) = 2.093599` по её собственной процедуре и `2.105153` по Медхи. Точный расчёт
даёт **2.105153** — значение Медхи, до последнего напечатанного знака. Случай не спорный:
бесконечнобуферный решатель, уже имеющийся в библиотеке
([EPIC-032](../epics/EPIC-032-bulk-service-waiting-moments.md), не разделяющий с помеченной цепью
ни строчки кода), независимо даёт то же число до семи знаков, а вероятность потери при `N = 200`
равна `3·10⁻¹²`, так что обе системы — одна и та же.

Механизм назван в самой статье: подгонка Паде ведётся при двух побочных условиях — воспроизвести
полную массу и первый момент. Остальное не связано ничем. Поэтому среднее переживает обращение
точно, а второй момент, ушедший на 0.55 %, — нет.

**Функция распределения вблизи нуля.** Для примера 4, `M/PH₂^(5,5)/1/N` при `λ = 6`, начиная с
`t = 4` совпадение держится на шести знаках и лучше. При `t = 2` три опубликованных источника уже
расходятся между собой: у Chaudhry и соавторов 0.618004 при `N = 300`, у Ю и Тана 0.610358 для
бесконечного буфера, — а при вероятности потери `10⁻¹¹` это одна и та же система. Точное значение
равно **0.612085**, и симуляция той же системы даёт 0.612577 ± 0.001862: четверть стандартной
ошибки до точного значения и 2.9 — до опубликованного.

Окрестность нуля — ровно то место, где рациональному приближению преобразования тяжелее всего,
потому что именно там распределение растёт быстрее всего.

**Честные границы доказательств.** По второму моменту симуляция **не** может быть арбитром:
кандидаты расходятся на 0.55 %, что далеко внутри её разрешающей способности, и отдельный тест
фиксирует это явно, вместо того чтобы приписывать ей поддержку, которой она не даёт. Вопрос
решается согласием двух независимых точных построений со значением Медхи плюс описанным выше
механизмом. Статья 2025 года закрыта пейволлом, поэтому её числа проверить напрямую не удалось;
воспроизводится здесь её открытая пуассоновская предшественница, метод которой она и расширяет.

### Что меняют коррелированные приходы

Приходящие заявки **не** видят стационарное по времени состояние, если поток не пуассоновский. Для
MAP правильное распределение — то, что наблюдается в моменты приходов, `π D1 / (π D1 1)`, и разница
тут не косметическая. Для приведённого выше двухфазного пачечного MAP прибор занят 34.2 % времени,
но занят при 50.8 % приходов: всплеск застаёт прибор, которого уже загрузил предыдущий всплеск.
Подстановка стационарного по времени закона раздувает `E(W)` с 0.3956 до 0.5756, то есть на
**+45 %**, — это несопоставимо больше любых погрешностей обращения, о которых идёт речь на этой
странице. Тест это фиксирует, арбитром выступает симуляция (0.3966).

**Проверка:** воспроизведение опубликованных пуассоновских таблиц выше; замкнутые формы в
вырожденных углах (`a = b = 1` при широком буфере — это обычная M/M/1, и среднее ожидание, среднее
пребывание и `P(W = 0) = 1 − ρ` совпадают до двенадцати знаков); закон Литтла `Lq = λ' E(W)` с
машинной точностью, в том числе при 70 % блокировок; вероятность потери против вероятности полного
буфера по PASTA; функция распределения против моментов интегрированием хвоста; однофазный MAP,
в точности воспроизводящий пуассоновский путь; совпадение с независимым бесконечнобуферным
решателем библиотеки; и пошаговый симулятор для MAP-случая, где опубликованных чисел не
существует. См. [EPIC-083](../epics/EPIC-083-map-ph-bulk-finite-buffer.md).

### Симуляция

**Класс:** `BulkServiceMapPhSim` (`most_queue.sim.bulk_map_finite`)

```python
import numpy as np
from most_queue.random.map_ph import MAPParams, PHParams
from most_queue.sim.bulk_map_finite import BulkServiceMapPhSim

sim = BulkServiceMapPhSim(a=3, b=8, capacity=25, seed=1)
sim.set_sources(MAPParams(D0=np.array([[-9.0, 0.6], [0.4, -1.4]]),
                          D1=np.array([[8.0, 0.4], [0.2, 0.8]])))
sim.set_servers(PHParams(alpha=np.array([0.3, 0.7]),
                         T=np.array([[-2.0, 1.0], [0.0, -5.0]])))
results = sim.run(total_served=50_000)
results.w[0], results.cdf(1.0, "v"), results.loss_probability
```

**Границы применимости.** Один прибор; время обслуживания группы не зависит от её размера
(вариант с такой зависимостью — отдельная и гораздо более тяжёлая линия работ, см.
[групповое обслуживание](batch.ru.md)); буфер обязан вмещать хотя бы `a`, иначе группа никогда не
соберётся. Размер цепи растёт как `N·a·m_s·m_a`, поэтому очень большие буферы при многих фазах
обходятся дорого; `N` порядка сотен при нескольких фазах считается свободно.

### Смежные модели библиотеки

- [Групповое обслуживание](batch.ru.md) — пуассоновское семейство с бесконечным буфером:
  Erlang- и H2-обслуживание, зависящие от размера группы интенсивности, нетерпеливость, несколько
  приборов.
- [Матрично-аналитические модели (MAP/PH)](map-ph.ru.md) — тот же коррелированный входной поток без
  группового обслуживания.
- [SLA / вероятность нарушения дедлайна](sla.ru.md) — что делать с точным хвостом, когда он есть.
