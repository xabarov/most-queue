## 2. Что реализовано и где теория заканчивается

Калькулятор возвращает равновесие, однородный worst-cycle throughput и
численный finite-input spectrum. `evolve` — saturated continuous stage map.
Отдельный integer DES не импортирует theory и отслеживает идентичность,
возраст, очередь, LPF-eviction и полный restart. FCFS admission и tie-breaking
заданы явно; смешение классов не принудительно пропорционально.

Время — итерация, память — reserved KV tokens. Этапы: execute → arrivals →
evict → admit. Учёт потерянной decode-работы не равен модели стоимости
prefill/swap/recompute в секундах. Случайные неизвестные длины не добавлены.
Memory area и спектр не выдаются как распределение задержки или recurrence
открытой очереди. Численные корни — диагностика с boundary/residual guard,
не сертифицированный Schur-тест общего degree-256 полинома.

## 3. Независимые арбитры

[Unit tests](../../tests/units/test_kv_cache_congestion.py) проверяют:

- 15 комбинаций S∈{0,2,10}, D∈{1,2,3,5,8}: суммирование stage area,
  fixed point и полный максимальный цикл; D=1 проверен отдельно.
- Непрерывную карту на `Fraction` для трёх законов длин, greedy/cap=1.5,
  30 шагов: независимые shift, overflow trimming и admissions.
- Полный class-stage Jacobian, построенный прямым дифференцированием
  admission по свободной памяти, а не companion-матрицей из коэффициентов F.
- Предельные полиномы: (2,3) имеет radius=1/√2;
  (2,4) содержит множитель (z+1), то есть unit-circle root.
- Точный тест Шура в рациональной арифметике, не численный root oracle.
  Для вещественного a0,...,an необходим строгий |an|<|a0|; следующий
  полином имеет b_j=a0*a_j−an*a_(n−j), j=0,...,n−1. Рекурсия доводится
  до константы с нормировкой, без floating-point округления.
- Ручной integer trace M=24,S=2,D=3; независимый divisible worst-cycle
  M=60: `[20,0,0]→[0,15,0]→[0,0,12]→[20,0,0]`, throughput=4.
  Общий integer-процесс не объявлен равным fractional theorem.
- Seed/replay, границы API, память, точное сохранение запросов и работы.

Балансы DES (warmup включён, горизонт не дренируется):

```text
initial_jobs + arrived = completed + unfinished
initial_work + executed_work = completed_work + discarded_work + remaining_work
```

В fluid-пути второй баланс проверяется с численной точностью; идентичности
свежего saturated supply не отслеживаются, поэтому request-conservation
DES не переносится на `evicted_mass`.

## 4. Воспроизведение и расхождения с печатным текстом

Для M=24,S=2,D=3 и `[2.5,2,1.7]` первое вытеснение появляется на шаге 7,
после него `[0,778/243,544/243]`; на шаге 16 получен `[0,0,4.8]`.
Worst cycle имеет throughput=1.6 против номинальных 2.
При cap=2 после перехода нет вытеснений. Однако точное исходное равновесие
остаётся неподвижным; исключительный balanced capture
`[48/13,24/13,72/65]` также проверен. Нельзя писать, что **каждое** начальное
состояние обязательно уходит на максимальный цикл. Balanced capture проверен
на коротком горизонте: roundoff не удостоверяет бесконечную точную орбиту.

При p=q=1/2, общих input lengths и decode (2,7):

| S | Finite spectral radius | Независимый точный Schur-тест |
|---|---|---|
| 14 | 1.009208699 | Неустойчив |
| 15 | 1.006072330 | Неустойчив |
| 17 | 1.000755951 | Неустойчив |
| 18 | 0.998482773 | Устойчив |
| 50 | 0.971176137 | Устойчив |

Сканирование целых S=0,...,19 даёт первый строго устойчивый **18**, тогда как
подпись Figure 3 называет 15. Коэффициенты взяты из конечной Eq.10, результат
согласован с прямым stage Jacobian и точной рациональной рекурсией Шура.
Это расхождение печатной подписи; программа авторов не исследована.

Example 9 / Figure 11 также описывает (2,3) как устойчивый для всех конечных S.
На S=0 полином `[1,2,1.5]` имеет radius=√1.5>1; S=1 даёт `[2,3,2]`
и radius=1 (boundary); первый строго устойчивый целый S=2.
Эти проверки **не опровергают** theorem о достаточно большом input length.
Они запрещают заменять finite-input анализ одним признаком GCD.

## 5. Синтетический эксперимент

[Скрипт](../../examples/kv_cache_congestion_experiment.py),
[полные параметры/результаты JSON](kv-cache-congestion-results-2026.json):

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 PYTHONPATH=. \
  .venv/bin/python examples/kv_cache_congestion_experiment.py
```

10 fluid trajectories: пять начальных состояний × greedy/nominal cap;
48 finite spectra: четыре пары D × двенадцать S;
24 integer DES-настройки × четыре seed 8000–8003. DES: 3000 итераций,
warmup=600, λ∈{.65,.9,1.15}*a*. Сравниваем одинаковые Poisson-приходы
при greedy/cap; итерационная duration исключена из JSON для воспроизводимости.
В эксперименте **явно выбран floor(a*)** как целый cap; API сам не округляет.

Некоторые средние по четырём репликациям (SE — between-seed standard error):

| M / S / D | λ | Greedy throughput ± SE | Cap / throughput ± SE | Greedy / capped final queue |
|---|---|---|---|---|
| 60 / 2 / 3 | 4.5 | 4.0000 ± 0 | 5 / 4.4891 ± .0313 | 1411.25 / 2 |
| 2440 / 10 / 40 | 1.8 | 1.2616 ± .0004 | 2 / 1.7792 ± .0046 | 1473.5 / .25 |
| 518 / 50 / (2,3) | 3.6 | 3.6008 ± .0275 | 4 / 3.5335 ± .0050 | 7.25 / 208.75 |
| 626 / 50 / (2,4) | 3.6 | 3.6015 ± .0235 | 4 / 3.5436 ± .0096 | 16 / 191 |

Homogeneous cap улучшает выбранные режимы; при overload очередь всё равно
растёт (λ=5.75, cap=5, throughput=5). В heterogeneous integer FCFS cap=4
не поддерживает навязанные fluid пропорции стадий: может снижать throughput
и не исключает все вытеснения. Поэтому таблица не доказывает универсальной
полезности cap/GCD и не является оценкой стационарной очереди.
Все 96 DES-прогонов прошли точные балансы запросов и decode-работы.
