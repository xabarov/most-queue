# Проверка динамического батчинга без ограничения пакета

Л1 / [EPIC-084](../epics/EPIC-084-dynamic-batching-unbounded.md), 2026-10-11.
Реализована численная аппроксимация модели Inoue с независимыми эталонами.
Новой модели, новой теоремы об усечении или аналитического хвоста времени ожидания
эта работа не заявляет. [API](../models/dynamic-batching.ru.md),
[машиночитаемый отчёт](dynamic-batching-results-2026.json).

## Вложенная цепь и необходимые моменты

Приходы пуассоновские с интенсивностью λ. Время пакета:
`H[b]=(αb+τ₀)X`, где `E[X]=1`, `E[X²]=κ=1+CV²`.
Для детерминированного, gamma/Erlang/экспоненциального и H2-семейств κ постоянно
по b. Условно по b времена независимы.

```text
A | H ~ Poisson(λH)
B' = A + 1{A=0}
E[A] = λ E[H]
E[A(A−1)] = λ² E[H²]
E[B] = λ E[H] + P(A=0)
E[B(B−1)] = λ² E[H²]
```

Последнее тождество объясняет, почему контролировать только вероятность края
недостаточно. Среднее ожидание — `E[B(B−1)]/(2λE[B])`; размер-смещённое
обслуживание случайной заявки — `αE[B²]/E[B]+τ₀`.
Простой удобно считать положительной формулой `P(A=0)/E[B]`, избегая вычитания
почти равных чисел в `1−λα−λτ₀/E[B]`.

В формуле (7) препринта для **обычного** второго момента A отсутствует
слагаемое `λE[H]`; формула (34) уже содержит его. Правильный обычный момент —
`λE[H]+λ²E[H²]`, а без первого слагаемого получается факториальный момент.
Независимый арбитр — определение смешанного пуассоновского закона и численная
квадратура его вероятностей, а не подстановка в эту же печатную строку.

## Устойчивость и конечность среднего ожидания

При `ρ=λα<1` отрицательный линейный дрейф даёт режим с конечным E[B].
Подстановка второго момента времени пакета даёт:

```text
(1−κρ²) E[B²] = (1+2κλ²ατ₀) E[B] + κλ²τ₀²
```

Правая часть положительна. Поэтому при `κρ²≥1` конечного E[B²] быть не может.
При `κρ²<1` квадратичный дрейф обеспечивает конечность второго момента.
Это вывод для реализованных масштабных семейств, а не новая теорема из статьи.

Следствие для API: `ρ<1` недостаточно для конечного ожидания при случайном времени
обслуживания. Например, при экспоненциальном времени нужны `ρ<1/√2`.
Фиксированное усечение искусственно делает все моменты конечными, поэтому проверка
области выполняется **до** построения матрицы, и её нельзя обойти через max_batch.
Даже в допустимой области тяжёлый хвост может не уложиться в вычислительный бюджет.

## Усечение и округление

Переходы за пределы N переносятся в N. Это не физический потолок пакета:
при настоящем потолке невзятые заявки сохраняются в очереди.
Крайне малые вероятности вне вычисляемого окна строки также переносятся на концы;
окно выбирается по квантилям с порогом 10⁻¹⁵ и запасом два счётчика.

Контроль автоматического режима:

1. Изменение E[B], E[B²], среднего ожидания, обслуживания и пребывания между
   двумя усечениями.
2. Доля E[B²] в верхних 20% состояний.
3. Невязки неусечённых тождеств первого и второго факториального моментов.
4. Стационарная невязка решённой конечной цепи.

Все должны быть не больше tolerance. Проверка момента не подменяет прямой расчёт:
моменты вычисляются из найденной PMF, а тождества проверяются отдельно.
Это **не сертифицированная оценка ошибки**. При недостаточном бюджете — исключение.
Фиксированное N всегда помечено `converged=False`, поскольку уточнение не проводилось.

В ходе проверки найден численный дефект чернового маршрута: решение разреженной
системы может оставлять положительные следы порядка машинного эпсилон в дальних
состояниях. После умножения на b² это портит редкие моменты. Добавлено уточнение
положительными итерациями переходной матрицы с взвешенным контролем, без отсечения
«слишком малых» истинных вероятностей.

## Независимые эталоны

- **α=0:** все строки цепи одинаковы. Для любого из пяти законов
  `E[B]=λτ₀+P(A=0)`,
  `E[B²]=E[B]+λ²κτ₀²`. Проверяется также простой и ожидание.
- **τ₀=0, детерминированное время:** независимая замкнутая проверка
  `E[Wq]=λα²/[2(1−ρ²)]`, `E[service]=α/(1−ρ²)`.
- **Gamma:** прямое интегрирование Poisson(λt) по плотности gamma для
  shape=0.5, 2.5, 5 сверяет переходы, включая нецелый shape.
- **Конечный физический потолок:** существующий `BulkServiceMM1Calc`, без общего
  кода решателя, при λ=1, α=0.1, τ₀=0.5 и экспоненциальном времени.
  Ожидание при cap=4,8,16,32: 0.3297189504; 0.3182175225; 0.3178411018;
  0.3178401785. Неограниченная модель: 0.3178401783.
  У CTMC отдельно задано усечение очереди 100; увеличение до 200 при cap=32
  меняет ответ менее чем на 2·10⁻¹⁶.
- **Событийная имитация:** пять законов, независимые seed=0…7, по 30 000 заявок после
  прогрева; сверяются ожидание, пребывание, средний пакет и простой. Допуск —
  4.5 стандартных ошибок репликаций плюс 0.5% относительный запас, из
  `tests/default_params.yaml`. Не используется ложная независимость заявок внутри пакета.
- **Тяжёлая нагрузка:** детерминированный режим ρ=0.9, 10 репликаций по 200 000
  измеряемых заявок, отдельный slow-тест.

Лемма 4, границы Теоремы 2 и закон Литтла — полезные проверки согласованности,
но они **не выдаются за независимую имитационную валидацию**.

## Сетка параметров и точность оценок

Воспроизведение:

```bash
python -m examples.dynamic_batching_experiment --output /tmp/dynamic-batching.json
pytest tests/units/test_dynamic_batching*.py tests/test_dynamic_batching_vs_sim.py
```

Сетка: α∈{0.001,0.0025,0.01}, τ₀/α∈{0,2,8,20},
ρ∈{0.1,0.3,0.5,0.7,0.9}, λ=ρ/α — 60 точек.
Это синтетическая параметрическая проверка, не воспроизведение измерений GPU.
Повторная генерация отчёта в том же окружении дала побайтово одинаковый JSON.
При tolerance=10⁻⁹ нужны до 1024 состояний; максимальная невязка факториального
момента 7.3·10⁻¹⁴, изменение при последнем уточнении 8.2·10⁻¹¹.

Максимальное завышение лучшей оценки на сетке — **7.3792%** при ρ=0.1, τ₀/α=8.
Для того же отношения τ₀/α при ρ=0.3 завышение **0.4042%**, не «точность до всех
знаков». При ρ=0.5 оно 0.004879%; далее убывает, как обсуждается у Inoue в §4.
В предельно малом зазоре округление может дать отношение bound/numerical чуть меньше
единицы (~10⁻¹³): это не контрпример к доказанной оценке.

Отдельная сетка усечений при λ=9, α=0.1, τ₀=0.2:

| N | Масса последнего состояния | Доля E[B²] в верхних 20% | Ошибка ожидания относительно N=1024 |
|---|---|---|---|
| 64 | 5.27e-4 | 0.0385 | 0.00329 |
| 128 | 8.29e-9 | 2.60e-5 | 1.15e-7 |
| 256 | 4.92e-17 | 5.14e-13 | 5.86e-13 |

Диагностики **не равны** ошибке ответа и не обязаны отслеживать её один к одному.
Исходное число «ошибка 5e-4 при хвосте 1.6e-8» не имело полного набора параметров
и здесь не объявляется воспроизведённым.

## Исправление статистики симулятора

Черновик удалял прогрев только из клиентских времён, но оставлял его в среднем
пакете и доле простоя. Теперь границы измерения совпадают для всех метрик.
Ручной событийный эталон: приходы 1,1.5,2,6, постоянное обслуживание 2;
первый пакет завершён в 3 и отброшен. Измеряемый пакет из двух заявок работает
с 3 до 5: ожидания [1.5,1], пребывания [3.5,3], простой 0, средний пакет 2.

Утверждение «пустой старт систематически смещает ожидание вверх» удалено:
несколько seed не доказывают знак переходного смещения. Ни универсальное
направление смещения, ни достаточность прогрева 20% не предполагаются.
