# Most-Queue 2.12

This release adds replay of measured LLM-serving arrivals, an advance-reservation
simulation policy and paired client TTFT/TPOT SLO comparisons. A fresh A40
experiment contains 690 successful requests: **13 of 14 frozen criteria pass**.
The failed criterion and substantial errors at tighter SLO thresholds are
published with the data.

## Serving APIs

- `most_queue.io.runpod.read_runpod_trace` imports saved request traces while
  preserving failed offers, actual token counts and explicit engine timestamps.
- `most_queue.sim.advance_reservation.AdvanceReservationSim` reserves available
  slots before compute starts and emits the first output token at prefill
  completion. It approximates the specified vLLM profile rather than emulating
  its asynchronous scheduler exactly.
- `most_queue.theory.continuous_batching.advance_reservation_calibration.fit_advance_reservation`
  fits isolated server-stage costs and a separate affine client residual.
- `most_queue.theory.continuous_batching.advance_reservation_validation.replay_advance_reservation`
  replays finite cohorts using exact server queue-entry arrivals and fixed costs.
- `compare_joint_slo` in that module compares both client conditions on each
  request and reports false passes and false failures.
- The original `fit_isolated_serving`, `replay_serving_cohort` and simulator
  remain available; the new policy does not replace them.

Joint compliance is computed from paired measurements, not a product of
marginal pass fractions. Incomplete or failed cohorts remain visible in outcome
summaries and are refused for paired replay accuracy evaluation.

## Fresh measurement results and limitations

Both fits were fixed from the original 27 isolated training requests before
collection. The fresh evaluation uses 21 warm-up and 669 evaluation requests
on A40 / Qwen3-8B / vLLM 0.32.0. Previously inspected v1 observations remain
[development data](../research/serving-v2-model-audit.md).

| Fresh metric | Baseline | Advance reservation |
|---|---:|---:|
| Median burst server-TTFT mean error | 43.05% | 7.69% |
| Maximum burst server-TPOT mean error | 28.44% | 4.75% |
| Maximum open-loop client-TTFT mean error | 9.75% | 4.48% |

For the primary client SLO, TTFT ≤1 s and TPOT ≤35 ms, the largest pass-fraction
error across six loaded series is **3.52 percentage points**, below its 10-point
limit. **The isolated server-TTFT maximum error is 20.68%, failing the 15% target.**
At the tighter diagnostic threshold TTFT ≤250 ms / TPOT ≤35 ms, pass-fraction
error reaches **31.87 percentage points** (29 false passes among 91 requests).
No observations were removed and no refitting or accuracy-based retry followed.

This is a bounded comparison for one pinned profile. It does not establish
production capacity, p99 accuracy, arbitrary SLO compliance or an independent-
sample confidence guarantee. Not every metric improves; all 14 criteria,
12 SLO thresholds and per-request results are in the
[full report](../research/serving-reservation-v2-results.md).

## Numerical correction

[`MMcDelayDependentServiceCalc`](../models/delay-dependent.md) now solves the
same boundary equations using exponentials anchored at the appropriate
endpoint. Earlier versions could amplify rounding errors into a huge incorrect
waiting mean at large thresholds on some numerical backends. Recompute affected
results. Erlang-C limits, the published finite-threshold example and simulation
checks pass without loosening tolerances.

An existing unseeded Fork-Join test now seeds its owned random generator;
its tolerance and production model are unchanged. Runpod progress reads have
bounded transient retries, and initial pod visibility has a fixed grace window;
mutating commands do not acquire automatic retries.

## Installation and reproduction

```bash
python -m pip install 'most-queue==2.12'
```

Examples and fixtures require a source checkout and are not bundled in the wheel:

```bash
git clone --branch v2.12 https://github.com/xabarov/most-queue.git
cd most-queue
python -m pip install -e .
python -m examples.serving_reservation_slo \
  --evaluation-fixture tests/fixtures/serving_measurements/runpod_qwen3_8b_a40_reservation_v2_20261114 \
  --frozen-fit configs/runpod/reservation-v2-fit.json \
  --output reservation-v2-results.json
```

This writes the complete report and deliberately returns **exit code 1** because
one frozen accuracy criterion fails. The audit itself reports `complete_success`.
The default example without an evaluation fixture uses labeled development data.
No GPU rental or network request is needed for the saved-data calculation.

Python **3.10+** remains supported. The public calculator convention remains
`set_sources()` / `set_servers()` / `run()`; individual models retain their
specified assumptions and result types.

## Validation

The complete local suite passes **4053 tests**; the corrected threshold model
also passes its 34 unit and 8 simulation tests on Python 3.10. All 690 GPU
requests and frozen scientific hashes were checked. All three campaign pods
are confirmed absent; total local cost estimate is **$0.555862** including disk.
Build, installation and publication evidence is retained in the
[release validation report](https://github.com/xabarov/most-queue/blob/main/docs/releases/2.12-validation.md).
