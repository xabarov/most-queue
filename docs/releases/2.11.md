# Most-Queue 2.11

This release brings the queueing models and LLM/GPU examples developed since
the published 2.9 package into one release. The existing `v2.10` Git tag identifies
an earlier October snapshot and is preserved. Version 2.10 was not published on
PyPI; 2.11 is the next package release.

## LLM serving and GPU scheduling

- Transient occupancy-dependent serving pools: piecewise Poisson traffic,
  an infinite FCFS queue, and queue-to-slot delay probabilities with explicit
  finite-state-projection truncation bounds.
- A reproducible [burst-recovery example](https://github.com/xabarov/most-queue/blob/v2.11/docs/models/transient-occupancy.md)
  with plots and machine-readable results; no GPU required.
- Detailed vLLM/SGLang result readers, joint request-level TTFT/TPOT SLOs,
  failed/pending outcome accounting, and a token-DES measurement adapter.
- [Isolated calibration with public GPU measurements](https://github.com/xabarov/most-queue/blob/v2.11/docs/serving_measurements.md).
  The simple model failed its held-out TTFT target (63.4% median relative error;
  TPOT 9.2%). This diagnostic workflow does not claim validated GPU queueing or
  loaded-serving predictions.
- Occupancy-dependent continuous batching, two-branch service, variable output
  lengths and clipping, and mixed prefill/decode iteration costs.
- Stage-aware mean TTFT, waiting-count reductions, infinite-queue continuation,
  stability checks and finite-core bounds for the documented models.
- KV-cache stability/congestion models and SMDP batching control.
- Multiserver-job scheduling, checkpoint/resume and protected useful-service
  policies, lifecycle-aware trace replay, capacity calendars and calibration
  tools for historical job traces.

These models have different assumptions and validation domains. Queue-to-slot
delay is not TTFT; mean TTFT does not determine TTFT/TPOT quantiles. Synthetic
examples are not hardware benchmarks, and floating-point truncation bounds do
not certify rounding errors. See the linked model pages before applying results.

## Other queueing models

- General-service and multiserver bulk service, impatience, size-dependent
  service rates, idle-refill waiting calculations and MAP/PH finite-buffer tails.
- Queueing-inventory systems with heterogeneous servers and phase-type service
  or replenishment, including corrected waiting-time calculations.
- Delay-dependent service, processor-sharing sojourn moments, value/deadline
  scheduling and controllable processing times.
- Additional network, reliability, priority, fork-join and staffing models.

## Corrections to review when upgrading

- Bulk-service abandonment includes departures behind a tagged customer;
  all-arrival SLA outcomes and local tagged-chain truncation bounds are exposed.
  H2 waiting means and earlier Inoue/cap comparisons were corrected. See the
  [correction report](https://github.com/xabarov/most-queue/blob/v2.11/docs/research/bulk-sla-revision-2026.md).
- Queueing-inventory waiting calculations were corrected for multiple servers;
  published results depending on the earlier calculations should be recomputed.
- Negative-customer models and restart calculations received validation and
  consistency fixes. Recompute dependent numerical results after upgrading.

## Installation and examples

Install the release:

```bash
python -m pip install 'most-queue==2.11'
```

Examples, research data and article materials live in the Git repository and are
not bundled into the wheel. To run the release's examples:

```bash
git clone --branch v2.11 https://github.com/xabarov/most-queue.git
cd most-queue
python -m pip install -e .
python -m examples.llm_burst_recovery
python -m examples.serving_measurements
```

Python 3.10 or later is required. The public calculator convention remains
`set_sources()` / `set_servers()` / `run()`. Individual models expose different
metrics; consult their result types and applicability checks.
