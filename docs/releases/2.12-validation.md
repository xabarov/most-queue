# Проверка Most-Queue 2.12

Дата: 14.11.2026. Статус: **завершено; 2.12 опубликован на PyPI и GitHub**. [Описание выпуска](2.12.md).

## Состав и совместимость

Добавлены строгий импорт собственных измерений Runpod, воспроизведение точных
серверных приходов, политика `AdvanceReservationSim`, отдельная калибровка
серверных затрат и клиентской добавки, совместная проверка TTFT/TPOT по каждой
заявке. Прежние симулятор, калибровка и воспроизведение сохранены.
Новая политика является приближением для описанного профиля vLLM, а не точным
воспроизведением его асинхронного планировщика.

## Программные проверки

- Итоговый полный прогон: `pytest tests/ -n 8` — **4053 passed, 19 warnings**,
  622,41 с. Использованы `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 PYTHONPATH=.`
  и интерпретатор `.venv` проекта.
- Ранее набор без `slow` прошёл 3974 теста. Последующие дополнения покрыты
  целевыми проверками и полным итоговым прогоном.
- Контроллер, жизненный цикл и бюджет: 220 целевых тестов, включая ограниченные
  повторы читающих запросов и короткое окно видимости сразу после создания pod.
- Black/isort и pylint для нового кода прошли; pylint библиотеки — 9,97/10,
  замечания остались в незатронутом коде.
- Существующий неинициализированный генератор случайных чисел в тесте Fork-Join
  получил фиксированный seed. Допуск и производственный код модели не менялись.
- GitHub CI выявил численную неустойчивость прежней записи модели с зависимостью
  обслуживания от ожидания при большом пороге. Исправление `62f7197` решает те же
  граничные уравнения через экспоненты, привязанные к соответствующим концам
  интервала. На Python 3.10 пройдены 34 модульных и 8 имитационных проверок.
  В 32 численно устойчивых случаях разница со старой записью не превышает
  8,5·10⁻¹⁵. Полный итоговый прогон включает это исправление.

## Измерения и публикация

Коэффициенты, модель, сценарий и 14 критериев зафиксированы до новых измерений
в [манифесте](../../configs/runpod/reservation-v2-freeze.json).
[Материал разработки](../research/serving-v2-model-audit.md) сохранён отдельно.
Две технически прерванные попытки и разрешение ровно одного дополнительного
выделения записаны в [дополнении](../research/serving-reservation-v2-operations-addendum.md).
Неполный снимок первой попытки исключён из проверки точности.

[Свежий опыт завершён](../research/serving-reservation-v2-results.md): 690 успешных
запросов, пройдены 13/14 критериев. Ошибка одиночного серверного TTFT — 20,68%
при пределе 15%. Для основного совместного SLO ошибка доли не превышает
3,52 п.п.; при TTFT 250 мс достигает 31,87 п.п. Все результаты сохранены,
коэффициенты не переобучались. Все 18 научных SHA256 неизменны.

Три pod подтверждённо удалены последующими GET и inventory. Общий учёт аренды:
3329 с, оценка $0,555862 с диском; биллинг провайдера пока не вернул записей.
Журнал закрыт, разрешение деактивировано. Оба прерывания сохранены отдельно.

## Упаковка и установка

Дистрибутивы собраны из `git archive` коммита
`8feca940fe42e0b76a31574aee828619389148b1`, на который указывает `v2.12`.
Wheel собран из sdist; оба файла прошли `twine check`. Проверены наличие всех
новых модулей и отсутствие окружения, учётных данных и исходных измерений.
Hatch также включает в sdist сопроводительные LICENSE/README наборов данных;
самих трасс и запускаемых примеров из `examples/` в дистрибутивах нет.

В чистом окружении Python 3.12 вне checkout проверены версия и источник импорта,
классическая M/M/n/r, нестационарная модель, исправленное ожидание при большом
пороге, совместный SLO, девять одиночных режимов нового симулятора, восстановление
пяти известных коэффициентов и импорты API. `pip check` не выявил конфликтов.
Окружение установки получило NumPy 2.5.4 и SciPy 1.18.1.

В отдельную папку скопированы только пример, необходимые служебные файлы,
конфигурации и измерения, без исходников `most_queue`. Пример, использующий
установленный wheel, воспроизвёл структуру отчёта и все **22 937** вещественных
значений при `rtol=1e-9, atol=1e-11`. Сохранены 13/14 критериев и ожидаемый
код выхода 1 для непройденной цели точности. Это не сбой установки.
