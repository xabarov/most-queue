# Точная вероятность нарушения SLA в системах пакетного обслуживания с ограниченным размером пакета и фазовым временем обслуживания

*Черновик статьи. Личные материалы, в git не попадают (см. `.gitignore`: `docs/статьи/`).
Код, на котором основана статья, — в основном репозитории most-queue, EPIC-066.*

## Аннотация

Системы пакетного (group/batch) обслуживания с временем обслуживания, зависящим от размера
пакета, — классическая модель для серверов динамического батчинга при инференсе нейронных
сетей и, в частности, больших языковых моделей (LLM). Операторов таких систем интересует не
только среднее время ожидания, а вероятность нарушения SLA/SLO — `P(W>D)` для заданного порога
`D`. Существующие точные результаты для времени ожидания в системах с batch-size-зависимым
обслуживанием (Banerjee, Gupta и др.) ограничиваются длиной очереди; единственный известный нам
результат для хвоста времени ожидания с batch-size-зависимым обслуживанием (Claeys и др.,
2013) — приближение в дискретном времени. Единственный известный точный результат для НЕПРЕРЫВНОГО
времени — классическая формула Чаудхри и др. (2023) — не учитывает зависимость времени
обслуживания от размера пакета. Мы заполняем это пересечение: точная вероятность нарушения SLA
`P(W>D)` для непрерывного времени, ограниченного окна размера пакета `[a,b]` (a=1) и фазового
(Erlang/H2, произвольный коэффициент вариации) batch-size-зависимого времени обслуживания, через
действие матричной экспоненты на явно построенном phase-type подгенераторе. Результат точно
регрессирует к известным частным случаям и подтверждён независимым имитационным моделированием.
Численное сравнение с опубликованной закрытой оценкой сверху среднего времени ожидания (Inoue,
2021) показывает, что при реалистичном (ограниченном памятью GPU) максимальном размере пакета
истинное среднее время ожидания может превышать эту оценку почти на порядок; сравнение с
приближением по моментам показывает систематическое завышение вероятности нарушения SLA в
глубоком хвосте на несколько порядков.

**Ключевые слова:** теория массового обслуживания, пакетное обслуживание, batch-size-dependent
service, фазовые распределения, SLA, вероятность нарушения дедлайна, инференс больших языковых
моделей, динамический батчинг.

## Abstract

Batch-service queueing systems with batch-size-dependent service times are the natural model
for dynamic-batching inference servers, including large language model (LLM) serving. Operators
of such systems care about the deadline-violation probability `P(W>D)`, not only the mean wait.
Existing exact results for waiting time in batch-size-dependent service systems are restricted to
queue-length distributions; the only known waiting-time TAIL result for batch-size-dependent
service (Claeys et al., 2013) is a discrete-time approximation. The only known exact continuous-time
waiting-time-distribution result (Chaudhry et al., 2023) does not allow service time to depend on
batch size. We fill this intersection: an exact deadline-violation probability `P(W>D)` for
continuous time, a bounded batch window `[a,b]` (a=1), and phase-type (Erlang/H2, arbitrary
coefficient of variation) batch-size-dependent service time, via matrix-exponential action on an
explicitly constructed phase-type sub-generator. The result regresses exactly to known degenerate
cases and is validated against independent discrete-event simulation. A numerical comparison with
a published closed-form upper bound on mean wait (Inoue, 2021) shows that under a realistic
(GPU-memory-bounded) maximum batch size the true mean wait can exceed that bound by almost an order
of magnitude; comparison with a moment-fit approximation shows systematic overestimation of
deep-tail SLA-violation probability by several orders of magnitude.

**Keywords:** queueing theory, batch service, batch-size-dependent service, phase-type
distributions, SLA, deadline-violation probability, large language model inference, dynamic
batching.

## 1. Введение

Ускорение инференса нейронных сетей на GPU существенно зависит от **динамического батчинга**:
объединения нескольких независимо поступивших запросов в один пакет (batch), обрабатываемый
сервером одновременно. Это даёт выигрыш в пропускной способности и энергоэффективности ценой
дополнительной задержки ожидания — запрос должен дождаться, пока сформируется пакет и пока он
будет обслужен [Inoue, 2021]. Применительно к инференсу больших языковых моделей (LLM) эта
задержка напрямую входит в метрику time-to-first-token (TTFT), для которой операторы всё чаще
формулируют требования service-level objective (SLO) в терминах вероятности, а не среднего:
`P(TTFT>D)<ε` для некоторого малого `ε` [QUARTZ, 2026; Tool-Augmented LLM Serving Under Firm
Deadlines, 2026].

Два структурных свойства реальных систем динамического батчинга отличают их от классической
модели пакетного обслуживания Bailey (1954):

1. **Время обслуживания пакета зависит от его размера.** Обработка батча из `b` запросов
   занимает больше времени, чем батча из одного запроса, но не пропорционально `b` — типичная
   эмпирическая зависимость близка к линейной с положительным свободным членом,
   `H^{[b]}≈αb+τ₀` [Inoue, 2021, уравнение (25)].
2. **Размер пакета ограничен сверху.** Память GPU ограничивает максимальный размер батча
   `b_max`; на практике `b_max` — конечное, часто небольшое (единицы-десятки) число, а не
   абстрактная бесконечность.

Настоящая работа даёт точную (не приближённую, не являющуюся оценкой сверху) вероятность
нарушения SLA `P(W>D)` для модели, сочетающей оба этих свойства, в непрерывном времени, с общим
(не только экспоненциальным) временем обслуживания пакета произвольного коэффициента вариации
(через фазовую, Erlang/H2, аппроксимацию).

## 2. Обзор литературы и позиционирование результата

### 2.1. Закрытая оценка среднего времени ожидания (Inoue, 2021)

Прямой практический прецедент — работа Inoue [Inoue, 2021], формулирующая сервер инференса как
batch-service очередь с batch-size-зависимым временем обслуживания и выводящая **закрытую
оценку сверху** среднего времени ожидания `E[W]` (Theorem 2 этой работы) при двух
упрощающих допущениях: (а) **неограниченный** максимальный размер пакета (при освобождении
сервера в пакет забираются ВСЕ ожидающие заявки), (б) **детерминированное**,
линейно-зависящее от размера время обслуживания пакета, `H^{[b]}=αb+τ₀`. Автор explicitly
указывает, что точный анализ даже для batch-size-зависимого M/M/1 труден, и что для случая
конечного `b_max` известен лишь алгоритмический (не замкнутый) матрично-аналитический подход
[Neuts, 1989].

### 2.2. Точные распределения для batch-size-зависимого обслуживания: только длина очереди

Начиная с работы Banerjee и Gupta [Banerjee, Gupta, 2012] и продолжая обширной серией работ
[Pradhan, Gupta, Samanta, 2015; Banerjee, Gupta, Chakravarthy, 2015; Gupta и др., 2018; Pradhan,
Nandy, Gupta, 2024; Barbhuiya, Gupta, Samanta, 2026], индийская школа теории массового
обслуживания детально проработала **точное** стационарное распределение ДЛИНЫ ОЧЕРЕДИ (и
содержимого сервера) для систем пакетного обслуживания с batch-size-зависимым, в том числе
фазовым (phase-type), временем обслуживания, при разных входных потоках (Пуассон, MAP, BMAP) и
дополнительных механизмах (vacations, group arrivals). Эти работы дают точное распределение
длины очереди в различные моменты времени (post-departure, pre-arrival, random epoch), но не
распределение ВРЕМЕНИ ОЖИДАНИЯ конкретной помеченной заявки.

### 2.3. Распределение времени ожидания: без batch-size-зависимости (точно) или с ней (приближённо)

Классический результат для времени ожидания в системе пакетного обслуживания с ОБЩИМ (но не
зависящим от размера пакета) временем обслуживания получен точно через метод корней
характеристического уравнения [Chaudhry, Datta Banik, Barik, Goswami, 2023] — развитие
полувековой линии работ с методом корней (roots method) для bulk-service очередей. Та же группа
авторов в 2025 году, расширяя метод на коррелированный (MAP) входной поток и общее
(rational-LST, R-type) время обслуживания, явно называет полученное распределение времени
ожидания **приближением** («Approximation to the phase-wise virtual waiting-time distribution»)
[Banik, Chaudhry, Barik и др., 2025] — то есть даже БЕЗ batch-size-зависимости точное решение
для коррелированного входа остаётся открытым. Единственная найденная нами работа, явно дающая
ХВОСТ времени ожидания ПРИ batch-size-зависимом обслуживании, — [Claeys, Steyaert, Walraevens,
Laevens, Bruneel, 2013], но это дискретное время (телекоммуникационная/ATM-модель) и явное,
заявленное самими авторами приближение.

### 2.4. Формулировка пробела и вклад данной работы

Пересечение условий «точно» × «непрерывное время» × «время ожидания (не только длина очереди)»
× «batch-size-зависимое обслуживание» не закрыто ни одной из найденных работ, включая самые
свежие публикации (2024–2026) той же исследовательской традиции. Данная работа закрывает это
пересечение для случая `a=1` (нет нижнего порога запуска пакета — типичный режим для
динамического батчинга, где сервер не ждёт накопления минимального числа заявок) и доводит
результат до вероятности нарушения SLA — метрики, напрямую востребованной операторами
GPU/LLM-инференса, но не рассматриваемой ни в одной из найденных работ этой традиции.

## 3. Постановка задачи

Рассматривается однолинейная система `M/PH^{[1,b]}/1`: пуассоновский входной поток интенсивности
`λ`; как только сервер освобождается и есть хотя бы одна ожидающая заявка, формируется пакет из
`min(b, j)` заявок, где `j` — число ожидающих (минимальный порог запуска `a=1`, то есть сервер не
простаивает, ожидая более одной заявки); время обслуживания пакета размера `i` имеет фазовое
(Erlang(`k`, `rate(i)`) или H2(`p1(i)`,`mu1(i)`,`mu2(i)`)) распределение, допускающее произвольную
зависимость параметров от `i` — в частности, эмпирически наблюдаемую линейную зависимость
среднего от размера пакета [Inoue, 2021].

Цель — вывести точное `P(W>D)` для `D≥0`, где `W` — время ожидания в очереди случайно выбранной
(по PASTA) заявки, без ограничения на распределение времени обслуживания, кроме его
принадлежности к фазовому классу.

## 4. Метод

### 4.1. Базовая цепь Маркова

Система моделируется усечённой (по длине очереди, `j≤N`) цепью Маркова с состояниями
`(i,φ,j)`, где `i∈{0,...,b}` — размер обслуживаемого пакета (`i=0` — простой), `φ` — текущая
фаза обслуживания пакета (для Erlang — номер пройденной фазы `0..k-1`; для H2 — выбранная при
старте ветвь `{0,1}`; не определена при `i=0`), `j` — число ожидающих заявок. Стационарное
распределение `π(i,φ,j)` находится прямым решением `πQ=0` для разреженного генератора `Q`
(построение и решение — без изменений относительно существующих калькуляторов библиотеки
most-queue, см. [most-queue, EPIC-012, EPIC-035, EPIC-036]).

### 4.2. PASTA-разложение времени ожидания

По свойству PASTA, заявка, приходящая в систему, видит стационарное распределение `π(i,φ,j)`.
Если сервер простаивает (`i=0`), заявка немедленно формирует (возможно, с кем-то ещё) новый
пакет: `W=0`. Если сервер занят, время ожидания заявки раскладывается на два независимых
слагаемых:

- **остаток текущего обслуживаемого пакета** — для Erlang это `Erlang(k-p, rate(i))`
  (оставшиеся `k-p` фаз, где `p` — застанная фаза); для H2, по марковости экспоненциальной
  фазы, это просто `Exp(mu_φ(i))` — остаток ТОЙ ЖЕ фазы, в которой застали пакет;
- **`⌊j/b⌋` полных последующих пакетов**, каждый размера ровно `b` (поскольку при
  освобождении сервера FCFS-пакеты формируются максимального размера, пока ожидающих
  достаточно) — для Erlang это строго последовательная цепь из `⌊j/b⌋·k` фаз ставки
  `rate(b)`; для H2 — КАЖДЫЙ из `⌊j/b⌋` последующих пакетов НЕЗАВИСИМО заново выбирает свою
  ветвь (`0` с вероятностью `p1(b)`, иначе `1`), то есть эта часть представляет собой
  ВЕТВЯЩУЮСЯ (не последовательную) phase-type цепь.

### 4.3. Точный хвост через действие матричной экспоненты

Для каждого занятого состояния `(i,φ,j)` с `π(i,φ,j)>0` строится явный конечный подгенератор
`T_{i,φ,j}` поглощающей цепи Маркова, представляющей разложение из §4.2 (начальный вектор
`α=e_1`, поглощение — достижение помеченной заявкой начала обслуживания). Хвост времени
ожидания, УСЛОВНЫЙ на этом состоянии, — классическая формула phase-type распределения:

```
P(W>t | i,φ,j) = α · exp(T_{i,φ,j}·t) · 1
```

Итоговый (безусловный) точный хвост:

```
P(W>t) = Σ_{(i,φ,j): i≥1} π(i,φ,j) · α · exp(T_{i,φ,j}·t) · 1
```

Для MM1/Erlang подгенератор `T` — двухдиагональная (последовательная) матрица; для H2 —
содержит ветвление (на каждом «слое», соответствующем очередному полному пакету, две
исходящие дуги вместо одной). Экспонента вычисляется не явным построением плотной матрицы (это
оказалось вычислительно непригодным — см. §6.1), а **действием** на единичный вектор через
разреженное представление (`scipy.sparse.linalg.expm_multiply`), что даёт точный результат без
ручного разбора случаев совпадающих/несовпадающих кратностей ставок, неизбежного при
классическом подходе частичных дробей для гипоэкспоненциальных/Coxian распределений.

### 4.4. Регрессионные тождества

При `b=1` (отсутствие батчинга) результат должен точно совпасть с классической формулой хвоста
M/M/1: `P(W>t)=ρ·exp(-μ(1-ρ)t)`. При `k=1` Erlang-калькулятор должен точно совпасть с
экспоненциальным (MM1) калькулятором; при `p1=1` H2-калькулятор должен точно совпасть с ним же
(вторая ветвь становится недостижимой). Эти тождества — не просто регрессионные тесты, а
необходимое условие корректности построения: расхождение в любом из них указывало бы на ошибку в
конструкции подгенератора.

## 5. Проверка

Все три регрессионных тождества §4.4 подтверждены с точностью до ошибок округления `float64`
(порядка `1e-16`). Независимо от регрессий, результат для batch-size-зависимого времени
обслуживания (где регрессионные тождества неприменимы) проверен против независимого
имитационного моделирования (дискретно-событийная симуляция, независимая реализация, не
использующая код библиотеки) для каждого из трёх калькуляторов, в нескольких точках `t`,
включая точки глубокого хвоста, где симуляция из `3×10⁶` выборок не дала НИ ОДНОГО события
превышения порога — точный результат в этих точках даёт малое, но ненулевое значение,
согласующееся по порядку величины с границей, которую могла бы дать симуляция большего объёма.

## 6. Численные эксперименты

### 6.1. Инженерное замечание: плотная экспонента непригодна

Первая реализация использовала явное построение плотной матричной экспоненты
(`scipy.linalg.expm`) на подгенераторе размера до нескольких сотен состояний (соответствующих
большому `⌊N/b⌋`). Время одного вызова составило **57 секунд** при реалистичном усечении
очереди (`queue_truncation=500`). Переход на действие экспоненты на вектор
(`scipy.sparse.linalg.expm_multiply`, без явного построения плотной матрицы) дал **идентичный**
результат за **0,19 секунды** — ускорение около 300 раз, необходимое условие практического
применения метода.

### 6.2. Сравнение со средней оценкой Inoue (2021)

Использованы параметры эмпирической линейной подгонки Inoue для батч-инференса ResNet-50 на
Tesla V100 (`α=0.1438`, `τ₀=1.8874`, те же единицы времени, что в [Inoue, 2021]), `λ=0.8`
(устойчивая система при любом `b_max≥2`: максимальная пропускная способность при `b_max=2`
составляет `2/(2α+τ₀)≈0.92`). Закрытая оценка Inoue для неограниченного батча:
`φ(λ,α,τ₀)=3.353`.

| `b_max` | Точное `E[W]`, CV=0,316 (Erlang) | Точное `E[W]`, CV=2,0 (H2) |
| --- | ---: | ---: |
| 2 | **5,005** | **35,064** |
| 4 | 1,196 | 7,796 |
| 8 | 1,074 | 5,640 |
| 16 | 1,073 | 5,217 |
| 32 | 1,073 | 5,199 |
| 64 | 1,073 | 5,213 |
| 128 | 1,073 | 5,216 |

При малом (реалистичном для памяти GPU) `b_max` истинное среднее время ожидания **превышает**
закрытую оценку Inoue — несмотря на то, что последняя формально является оценкой сверху: граница
корректно доказана для неограниченного батча и не распространяется на ограниченный случай. При
коэффициенте вариации `CV=2` (разумное предположение для батча со смешанными по длине
запросами, типичными для LLM-инференса) расхождение при `b_max=2` достигает почти **десятикратного**
значения. При больших `b_max` (приближение к режиму Inoue) точное значение остаётся ниже
границы — граница верна именно там, где и была выведена, но не несёт информации о своей
неприменимости при малом `b_max`.

### 6.3. Сравнение с приближением по моментам (подгонка SLA по двум моментам)

Для Erlang-случая (CV=0,316) сравнивается точный хвост с результатом стандартного подхода
«подгонка 2–3 моментов под H2/Gamma, вычисление хвоста подогнанного распределения» — широко
используемого на практике приёма, когда точный метод недоступен.

| `b_max` | `D` | Точная `P(W>D)` | Подогнанная (2 момента) | Относительная ошибка |

| 2 | 5 | 3,7035·10⁻¹ | 3,7107·10⁻¹ | +0,19% |
| 2 | 10 | 1,3255·10⁻¹ | 1,3331·10⁻¹ | +0,57% |
| 2 | 20 | 1,6981·10⁻² | 1,6906·10⁻² | −0,44% |
| 8 | 5 | 2,7386·10⁻⁴ | 2,5296·10⁻³ | **+824%** |
| 8 | 10 | 5,6797·10⁻⁹ | 2,4628·10⁻⁶ | **+43 261%** |
| 8 | 20 | 3,3642·10⁻¹⁸ | 1,6570·10⁻¹² | **+4,93·10⁷%** |
| 16 | 5 | 2,4137·10⁻⁴ | 2,5019·10⁻³ | **+937%** |
| 16 | 10 | 1,0582·10⁻⁹ | 2,4014·10⁻⁶ | **+226 833%** |
| 16 | 20 | 5,7739·10⁻¹⁹ | 1,5685·10⁻¹² | **+2,72·10⁸%** |

При умеренно глубоком хвосте (`b_max=2`, где `D` лишь в несколько раз превышает среднее)
подгонка по двум моментам работает приемлемо (ошибка <1%). Но при малом среднем времени
ожидания и дедлайне, уходящем в ДЕЙСТВИТЕЛЬНО глубокий хвост (во много раз больше среднего —
типичный для GPU/LLM SLA режим, где цель — `P(нарушение)<0,1%`), подгонка по моментам
**систематически и drastически переоценивает** вероятность нарушения SLA — на один-два порядка
при умеренной глубине хвоста и на много порядков при истинно глубоком хвосте. Это ожидаемо
(подгонка двух моментов не обязана верно восстанавливать форму далёкого хвоста), но впервые
количественно продемонстрировано для данного класса систем именно в практически значимом
режиме.

## 7. Ограничения

Результат ограничен случаем `a=1` (нет нижнего порога запуска пакета); случай `a>1` требует
отдельного («idle-refill») анализа и остаётся открытым (как и для точных моментов, см.
[most-queue, EPIC-032]). Численное сравнение использует параметры подгонки Inoue для
ResNet-50-инференса (не прямую LLM-трассу) и контролируемый синтетический CV, а не измеренную
изменчивость реального батч-инференса LLM — это управляемое численное исследование, а не
воспроизведение конкретной продакшн-системы. Сравнение с оценкой Inoue выполнено только по
среднему (`E[W]`); сравнение с подгонкой по моментам для хвоста выполнено только для
Erlang-случая низкой изменчивости.

## 8. Заключение

Получена и верифицирована точная вероятность нарушения SLA для системы пакетного обслуживания с
ограниченным (реалистичным для GPU-памяти) максимальным размером пакета и фазовым,
batch-size-зависимым временем обслуживания произвольного коэффициента вариации — результат,
закрывающий пересечение условий, не покрытое ни классической линией работ по точному
распределению длины очереди для batch-size-зависимого обслуживания, ни единственным известным
(приближённым, дискретно-временным) результатом для хвоста времени ожидания с такой
зависимостью. Численно показано, что пренебрежение ограничением размера пакета может занижать
истинное среднее время ожидания почти на порядок, а приближение по моментам — занижать точность
оценки вероятности нарушения SLA в глубоком хвосте на несколько порядков; оба эффекта напрямую
релевантны практике SLA-ориентированного управления GPU/LLM-инференс-серверами.
