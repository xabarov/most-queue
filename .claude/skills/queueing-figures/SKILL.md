# Рисунки для статей по теории очередей

Частный случай общего приёма matplotlib-рисунков для печати, конкретизированный под наши статьи
(сверено с уже работающими `docs/статьи/batch-service-sla/make_figures.py` и
`docs/статьи/batch-service-sla-single/make_figures.py` -- бери оттуда готовый блок стилей, не пиши
с нуля). Статьи печатаются **в оттенках серого** (Труды ВКА) -- значит цвет никогда не единственный
способ различить серии.

## Обязательный блок стиля

```python
plt.rcParams.update({
    "font.family": "serif",
    "font.serif": ["DejaVu Serif"],   # приближение к PT Serif тела статьи в XeLaTeX
    "font.size": 10.5,                # примерно кегль основного текста статьи
    "axes.titlesize": 10.5,
    "axes.labelsize": 10.5,
    "legend.fontsize": 9.5,
    "xtick.labelsize": 9.5,
    "ytick.labelsize": 9.5,
    "axes.linewidth": 0.8,
    "lines.markeredgewidth": 0.8,
    "mathtext.fontset": "dejavuserif",
    "savefig.bbox": "tight",
    "savefig.pad_inches": 0.03,
})
```

## Печатно-безопасное различение серий

Каждая серия -- **свой marker И свой linestyle**, цвет -- только дополнительный (третий) канал
(чёрный/тёмно-серый/светло-серый), никогда не единственный:

```python
SERIES_STYLE = {
    "a": {"marker": "o", "linestyle": "-",  "color": "#000000", "label": "..."},
    "b": {"marker": "s", "linestyle": "--", "color": "#595959", "label": "..."},
    "c": {"marker": "^", "linestyle": "-.", "color": "#a6a6a6", "label": "..."},
}
```

Опорная/справочная линия (граница, асимптота) -- `linestyle=":"`, без маркера, тоже чёрная/серая.
Сетка -- только `axis="y"`, `linewidth=0.3`, светло-серая (`#bfbfbf`), `ax.set_axisbelow(True)`.
Верхняя и правая рамки убираются (`ax.spines[...].set_visible(False)`).

**Перед сдачей рисунка** -- открой PNG и посмотри на него в оттенках серого (или распечатай
мысленно): если две серии неразличимы без цвета, это брак, а не мелочь.

## Размер и формат

- `figsize` в дюймах под реальную ширину колонки в LaTeX (для `\includegraphics[width=...]` без
  последующего масштабирования артефактами) -- в прецедентных статьях `(4.0, 3.0)`.
- `dpi=300` на создании фигуры.
- Сохранять **и** `.png` (для быстрого просмотра), **и** `.pdf` (векторный, для фактического
  включения в LaTeX) -- `fig.savefig(path.with_suffix(".png")); fig.savefig(path.with_suffix(".pdf"))`.
- Никакого заголовка `ax.set_title(...)` внутри рисунка -- подпись идёт в тексте статьи как
  `Рисунок N.` (`\captionof{figure}{...}` в `main.tex`), не дублируется на самом изображении.
- `plt.close(fig)` после сохранения каждой фигуры (несколько фигур в одном скрипте -- частый случай).

## Откуда брать числа

`make_figures.py` **не** пересчитывает ничего заново -- он читает уже посчитанные числа (JSON в
`works/<slug>/comparison.json` или прямой вызов того же калькулятора most_queue с теми же
параметрами, что в сравнительном скрипте статьи), чтобы числа на рисунке и в таблицах статьи
совпадали ровно, без риска разъехаться после правки одного из двух мест.

## Процесс при добавлении/правке рисунка

1. Поправить/написать `make_figures.py`, прогнать (`.venv/bin/python docs/статьи/<slug>/make_figures.py`).
2. Открыть получившийся PNG (`Read` умеет показывать изображения) -- **визуально проверить**:
   читаемость подписей осей, отсутствие наложений легенды на кривые, различимость серий без цвета.
3. Перекомпилировать `main.tex` (`latexmk -xelatex -interaction=nonstopmode main.tex`, дважды) и
   посмотреть на страницу целиком -- рисунок в контексте текста/подписи, а не изолированно.
4. Только после визуальной проверки на обоих шагах считать рисунок готовым -- компиляция без ошибок
   не гарантирует, что рисунок читаем.
