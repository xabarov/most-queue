## Почему Most-Queue?

- **Аналитика и симуляция вместе.** Почти у каждого аналитического калькулятора есть парный
  дискретно-событийный симулятор, а тесты сверяют их между собой. Быстрые точные числа —
  и способ их проверить.
- **Модели, которых нет в других open-source пакетах**: аналитика size-based дисциплин
  (SRPT, SJF, PSJF, SPJF с ML-предсказаниями размеров, FB/LAS), vacation-модели M/G/1,
  отрицательные заявки (RCS / disaster), ненадёжные приборы, многоканальные фазовые системы
  методом Такахаси–Таками (включая CV < 1 через complex-fit H₂).
- **Моменты, а не только средние**: начальные моменты времени ожидания и пребывания,
  вероятности состояний, загрузка — с единым API `set_sources() / set_servers() / run()`.
- **Чистый Python + NumPy/SciPy**, ставится через pip, лицензия MIT.

## Быстрый старт: теория против симуляции за 20 строк

```python
from most_queue.theory.fifo.mmnr import MMnrCalc
from most_queue.sim.base import QsSim

# Аналитический расчёт M/M/3 с конечной очередью
calc = MMnrCalc(n=3, r=100)
calc.set_sources(l=2.0)
calc.set_servers(mu=1.0)
theory = calc.run()

# Та же система — симуляцией
sim = QsSim(3)
sim.set_sources(2.0, "M")
sim.set_servers(1.0, "M")
experiment = sim.run(100_000)

print(f"Среднее ожидание: теория {theory.w[0]:.3f} vs симуляция {experiment.w[0]:.3f}")
# Среднее ожидание: теория 0.444 vs симуляция 0.448
```

## Новости

- **2026-10, текущие исходники** — **Availability-aware история приходов**:
  устраняет артефакт completed-prefix staleness (лаг до 8.2 дня), строя
  donor-историю приходов из submit<cutoff поверх уже распарсенной популяции
  completed+cancelled(+failed/timeout/node_failed), не останавливаясь на
  первом незавершённом к cutoff задании. Lag падает до минут/часов, donor-пул
  примерно удваивается, но это не равномерное улучшение точности: эффект на
  ошибку очереди противоположен на SDSC и Kalos. 16 юнит-тестов, 792
  расписания, побайтовый повтор, независимый аудит.

  четыре заданных заранее периода SDSC SP2, семь вариантов нагрузки, 1368 replay.

  с 94.57% до 44.12%, но эффект зависел от периода; уточнение K часто вредило.
  Блоки рангов лучше воспроизводят корреляции без устойчивого выигрыша
  по задержкам и p99-решениям. Это диагностика выбранной подвыборки, не причинный

- **2026-10, текущие исходники** — **Калибровка обслуживания на реальной трассе**:
  SWF-адаптер с аудитом и SHA-256, временной holdout завершённой истории SDSC SP2;
  эмпирическое, Exp, PH и lognormal-обслуживание для шести MSJ-дисциплин.
  В 594 replay все четыре модели сохранили лучший выбор по mean T, но сильно
  занизили задержки первых двух блоков; выбор по p99 отличался от контроля.
  Это условная историческая выборка завершённых работ, не реконструкция кластера.
  [Протокол](docs/real_trace_calibration.md),
  [результаты](docs/research/real-trace-calibration-results-2026-10.md).
- **2026-10, текущие исходники** — **MSJ с неэкспоненциальным обслуживанием**:
  PH-FCFS для малых систем и сравнение backfilling/packing на общих трассах.
  Прогнозы по историческим признакам, калибровка по ресурсным группам и
  возрастной Kaplan–Meier по цензурированным наблюдениям. MSFQ — one-or-all;
  ServerFilling — отдельная модель для степеней двойки с бесплатным
  preemptive-resume. Отдельный `MsjCheckpointSim` учитывает время и занятые
  ресурсы checkpoint/resume, различая выделенную и полезную загрузку.
  Опция `min_service_time` защищает каждый полезный интервал; её длительность
  можно выбирать по независимой истории, не подстраивая под тестовые результаты.
  В 832 парных sensitivity-прогонах overhead мог устранить преимущество packing;
  граница зависела от нагрузки, универсального порога стоимости нет.
  Ещё 1920 прогонов защиты показали выигрыш против SF без защиты при большой цене вытеснения;
  на обоих меньших уровнях цены исторический подбор оставил защиту выключенной.
  [Методы и API](docs/models/msj.ru.md), [результаты](docs/research/msj-packing-results-2026-10.md),
  [цена checkpoint/resume](docs/research/msj-checkpoint-results-2026-10.md),
  [результаты защиты полезного интервала](docs/research/msj-protected-service-results-2026-10.md),
  [roadmap](docs/roadmaps/msj-ph-backfilling.md). Симуляционные результаты не

- **2026-09** — **Волна реализма, часть 2: Erlang везде, batch-size-зависимые параметры, точные
  моменты**: время поставки в **queueing-inventory** обобщено с `Exp(θ)` на **Erlang-подогнанное**
  (фазовое измерение нужно только там, где заказ может быть в пути — впервые в этом семействе
  фазовых моделей); модель гетерогенных серверов получила **Erlang-подогнанное (CV≤1) обслуживание**
  как комплемент к H2-случаю, с реальной ошибкой разделения ставок (уход vs продвижение фазы),
  пойманной через намеренно невырожденную регрессионную проверку; параметры **группового
  обслуживания** (Erlang и H2) теперь могут зависеть от размера батча (реализм динамического
  батчинга LLM/GPU), а Erlang-случай получил **точные моменты W** (не только среднее) — перенос
  PASTA-техники EPIC-032 на фазово-расширенную CTMC. Полная разбивка — в
  [реестре эпиков](docs/epics/README.md) (EPIC-040…EPIC-043).
- **2026-09** — **Волна реализма: гетерогенные ветви, общее обслуживание, admission control**:
  **fork-join** обобщён на гетерогенные ветви, series-parallel DAG задач и (n,k)-join (точные
  моменты порядковых статистик, замкнутая форма Pareto); **групповое обслуживание** обобщено с
  экспоненциального на фазовые подгонки **Erlang** (CV≤1) и **H2** (CV≥1), с точными моментами
  N/W и авто-диспетчером, выбирающим семейство по CV; точный **admission control по дедлайну**
  (приём/отказ при поступлении по собственной дедлайн-достижимости, Exp(θ) дедлайн — решено через
  функциональное уравнение level-crossing и извлечение моментов усечёнными степенными рядами,
  после того как «очевидное» упрощение оказалось математически неверным); и **queueing-inventory**
  обобщена на `c` гетерогенных серверов (расщепление состояний + сложенный граничный QBD-суперблок)
  и, ещё на шаг дальше, на **H2-подогнанное (неэкспоненциальное) время обслуживания на каждый
  сервер** — у каждого сервера теперь может быть своё реалистичное распределение времени
  обслуживания вместо единой общей ставки. Полная разбивка — в
  [реестре эпиков](docs/epics/README.md) (EPIC-030…EPIC-039).
- **2026-09** — **Волна приоритетов, инвентаря и планирования**: **приоритеты M/M/2 с
  гетерогенными серверами** (точная не-birth-death CTMC, механическое построение состояний);
  queueing-inventory обобщена на **lost-sales**, полную политику **(s,S)** (не только (0,S)) и
  **многоканальный M/M/c** случай (точный QBD со сложенным граничным суперблоком, точно
  сводится к M/M/1 при c=1); и **EDF (Earliest Deadline First)** как реальная дисциплина
  обслуживания, а не post-hoc SLA-метрика — намеренно только DES, поскольку точный
  конечномерный анализ EDF оказался действительно открытой задачей (четыре кандидата на точное
  сведение проверены и опровергнуты численно/аналитически; см.
  [`docs/research/edf-scheduling-2026.md`](docs/research/edf-scheduling-2026.md)).
- **2026-09** — **Волна SLA и точных расширений**: горизонтальный слой **SLA/вероятность
  нарушения дедлайна** (`P(W > D)` и SLO-квантиль по моментам — поверх *любой* модели из таблицы
  выше; пример LLM-serving TTFT SLO); точный **тяжёлохвостый (Pareto) fork-join** (замкнутая
  форма максимума n через Beta-функцию, без аппроксимации); **machine repair с двумя
  гетерогенными ремонтниками** (не-birth-death CTMC техника Krishnamoorthi); первая
  **queueing-inventory система** (M/M/1 с расходуемым при обслуживании запасом, пополнение (0,S),
  backorder — точный QBD, переиспользующий решатель MAP/PH-стека). Обзор литературы за каждым —
  в папке [research](docs/research/).
- **2026** — **Волна масштаба и динамики**: **балансировка нагрузки** в mean-field-пределе
  (power-of-d / JSQ / JIQ — «power of two choices» современных диспетчеров); **polling-системы**
  (один сервер обходит Q очередей со switchover, exhaustive/gated, псевдо-закон сохранения
  Boxma–Groenevelt); и **нестационарная Mt/M/c** с переменной нагрузкой (приближения PSA и MOL
  для пиков спроса — штат колл-центров, autoscaling). Каждая с парным симулятором и тестами.
  См. [обзор трендов](docs/research/queueing-trends-2026.md).
- **2026 (v2.9)** — **Датацентр- и многоприоритетная волна**: **RDR** для многоканальных
  многоклассовых прерывающих приоритетов (M/M/k и M/PH/k, точный + RDR-A, дисперсия времени
  отклика по классам); модель **multiserver-job** (заявка занимает несколько серверов сразу —
  время отклика FCFS и устойчивость насыщенной системы, первая open-source реализация);
  **Age of Information** (средний и пиковый AoI); очереди с **групповым обслуживанием** для
  батчинга LLM-инференса; **кривые graceful degradation** для планирования с предсказаниями.
  См. [обзор трендов](docs/research/queueing-trends-2026.md).

- **2026** — **Матрично-аналитический MAP/PH-стек**: PH-распределения и MAP-потоки
